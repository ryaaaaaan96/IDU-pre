# transmit

转发模块提供解析、映射、初始化和维护能力，不创建自身执行线程或工作队列。

应用先创建并启动独立接收与配置队列，通过 `tr_modbus_bind_execution()` 绑定到接口。
两个队列不能相同；配置工作可能等待接收队列排空，不能在同一队列内形成循环等待。
队列及其栈由应用管理，生命周期覆盖服务运行期；绑定在启动时完成，运行期不替换。

- `tr_modbus_init_server()` 开启底层服务，隔离模式必须先绑定执行上下文。
- `tr_server_init()` 显式初始化服务配置，`tr_server_service()` 只维护已初始化服务。
- `tr_forward_init()` 装配指定逻辑入口并初始化服务，`tr_forward_service()` 只维护已装配入口。

未初始化时，维护入口返回 `-ENODEV`，不会首次启动；配置、写回调及入口映射必须常驻。
应用显式决定站号和维护调用时机，不依赖本地采样循环。
RAW 与完整 RTU 报文转换使用 [`modbus_support`](../modbus/README.md)；
请求来源、接收占用、发送错误、静默完成通知及协议段仍由本模块维护。
公共 Modbus 兼容实现通过可选内部钩子调用本模块的转发处理；本模块选择
`MODBUS_SUPPORT_SERVER_HOOKS`，纯采集构建不需要这些转发钩子。
非隔离、非阻塞的直接 Zephyr 接入仍可使用其子系统工作队列，不为此创建模块线程。
