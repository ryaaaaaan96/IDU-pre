# 端口后端扩展

本目录预留可复用的物理/传输后端。当前没有真实驱动适配实现；
可运行的模拟后端位于 [`tests/vport`](../../../tests/vport/src/main.c)。
注册与线程契约见[模块说明](../README.md)。

核心只依赖 `vport_backend_ops`，具体适配器按需编译：

| 后续适配器 | 使用的 Zephyr 能力 | 后端职责 |
| --- | --- | --- |
| CAN | `can_send()`、RX filter | 转换 ID/帧标志与 DLC，按能力配置硬件过滤，接收交核心分流 |
| UART | UART async 或 interrupt API | 有序 RX 片段、缓冲生命周期、发送完成/超时 |
| RS485 | UART 加 DE/RE 控制 | 复用 UART 能力，管理半双工方向及收发切换时序 |
| 网络 | socket API | TCP 流与 UDP 报文边界、peer/连接代次、断开与重连 |

各后端提供 `vport_link_config` 的操作与实例上下文，产品配置完成路由注册；
适配器不直接调用 collect/transmit，也不识别点号或解析业务协议。
为同一控制器安装的驱动 RX 入口应由适配器统一管理，不能依赖重叠硬件过滤器
会把同一帧投递给每个回调；逻辑分流由核心完成。

后端可自行管理硬件恢复和网络连接，但必须让过期连接令牌失效，
并在流缺口后调用 `vport_rx_gap()`。硬件开启接收应晚于 `vport_init()` 成功。
`send` 返回错误应保留真实错误，不把“已排队”报告为“已发送完成”。
发送锁只在注册的 link 内有效；多个连接若共享额外的半双工物理资源，
该资源仍需在共同后端中统一仲裁。

增加实现时为对应适配器添加独立 Kconfig 依赖，核心 `CONFIG_VPORT`
不自动选择 `CAN`、`UART_ASYNC_API` 或网络栈。
