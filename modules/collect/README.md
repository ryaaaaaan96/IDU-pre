# collect

应用显式注册数据连接，`co_init_bus()` 只登记采集总线，不安装 DP 参数后端或参考下发函数。

- `co_set_data_callbacks()` 复制样本和设备初始化处理函数，须在启动工作任务前调用。
- `dp_accept_samples()` 可直接作为样本处理函数；它复制入队，初始化同步采样时还等待处理结果并检查质量。
- `dp_initialize_acquired_device()` 可直接作为设备初始化后处理函数，处理 DP 初始化及参数反馈同步。
- `co_parameter_transport()` 提供可交给 `dp_params_set_transport()` 的同步读写后端。
- 使用参考下发接口时，由应用显式调用 `dp_para_reg_set_func(co_dp_fast_set)`。

未注册样本消费者时，采集发布返回 `-ENOTCONN`，不会隐式修改 DP。
参数回调在事务锁内执行，可以进行有界通信等待，但不能再次进入参数事务接口。
配置和回调上下文须覆盖运行期；运行中不支持替换数据连接。

`co_polling_init()` 检查总线就绪并启用调度，不创建线程。应用随后为每条实际采集总线创建工作线程，
以 `co_bus_task()` 为入口，首参数传 `(void *)(uintptr_t)bus_id`。
模块保留请求队列、调度和等待；同步读写不要求周期工作线程已经启动。
内部 `state.c` 集中管理采集阶段、到期时间、初始化推进及重试预算；总线任务执行返回的计划，
不再次解读在线/离线状态。组包和请求竞争仍由总线任务管理。
总线状态/队列容量由 `CO_MAX_BUSES` 控制，工作线程栈由应用使用 `CO_STACK_SIZE` 显式声明。

Modbus 客户端直接使用 Zephyr 协议接口，RAW 编解码和公共兼容处理依赖
[`modbus_support`](../modbus/README.md)，不引用 transmit 目录。
RAW 事务身份、接收占用及完成处理仍归本模块。

参考采集表用 `FLAG_INITIALIZE` 标记上线初始化读；不设置该标记时，周期 0 不会产生初始化请求。
初始化与正常轮询按声明顺序组织，只合并同设备、功能码、阶段、周期及优先级兼容的连续行。
组包在任务栈上完成，不复制整张只读点表；按寄存器、载荷及 DP 批量容量拆分，不跨空洞或拆半个测点。
显式 `co_poll(index)` 保留指定一行的诊断接口，自动调度和设备初始化采用组包。

`co_set_device_policy()` 在启动前为每台设备登记常驻只读策略，包含额外重试次数、最长异常时间和掉线探测间隔。
离线自动探测每周期仅发送首包一次，不使用初始化/正常轮询的重试预算；
失败后从本次完成时刻起等待 `probe_ms`，再开始下一次探测。
登记后任务按初始化、正常轮询、答复异常和掉线四状态运行；未登记时仍可使用原有手动采集能力。
自动初始化只读取初始化组，不重放业务 INIT 或已保存的下发目标；显式 `co_initialize_device()` 仍执行注册的初始化后处理。
显式读写不自动重试，错误仍记录，但失败不驱动自动轮询状态。有效异常应答证明通信存在，不代表数据可用。
状态的 `state` 表达采集阶段，`online` 单独记录通信是否已确认；`last_error` 在成功后保留，`error` 表示最近操作结果。

应用可将 `dp_invalidate_acquired_device` 注册到 `co_data_callbacks.offline`，由真实掉线转换触发，
保留最后数值、使该设备所有采集点通信失效，并隔离排队旧样本；各点成功采样后才恢复。
该回调不持 CO 状态或物理事务锁。`co_device_status()` 返回一致 RAM 快照，
`co_clear_device_errors()` 仅清错误与请求计数，不改变阶段、探测时间、质量或触发通信。
