# 工作缓冲区与系统堆

DP 登记时一次分配私有节点及该设备的全部点数据；应用只提供只读点表。
当前 `COMMON_VALUE_WORDS=16`，`value_t` 32 B，`dp_point_data_t` 36 B；
ARM 上私有节点头 16 B，本机 24 点一次申请 880 B（含头、不含堆开销）。
运行数据只保留点值和秒级更新时间。

参数直接使用设备点数据作为缓存；首次访问参数时再申请暂存值、已落盘值及提交镜像，
当前参数工作区为 2816 B。登记及参数工作区常驻到重启，不提供运行中注销。
失败不挂入设备目录，可重新登记；参数挂载错误由状态接口报告。

IAP 的位图、数据包、SGZ 与 Flash 写工作区由 `iap_init_config()` 一次申请，
失败时关闭 Flash 区域且不启动任务。SGZ/QuickLZ 纯算法接口仍由调用者提供工作区。

## 堆容量

所有模块共享同一个系统堆。`CONFIG_HEAP_MEM_POOL_SIZE` 为 0 时，Zephyr 使用
`HEAP_MEM_POOL_ADD_SIZE_*` 贡献之和：

| 配置后缀 | 当前预算（字节） |
| --- | ---: |
| `DATAPROCESS` | 2048 |
| `DP_PARAMS` | 4096 |
| `IAP` | 12288 |
| 合计 | 18432 |

2026-10-28 默认 MCUboot + IAPv3 构建系统堆为 18,524 B（含分配器开销）。IAP 预算覆盖
`receiver_buffers`：512 B 镜像写入缓冲、4.25 KiB 解包工作区、1 KiB 报文、
按容器位图约 4 KiB 及扇区位图 16 B。容器上限与板级暂存分区同为 512 KiB，
改任一项须同步 `CONFIG_IAP_MAX_CONTAINER_SIZE`。

`HEAP_MEM_POOL_ADD_SIZE_DATAPROCESS` 需要覆盖各设备节点头、点数乘以
`sizeof(dp_point_data_t)` 和分配器开销。新增设备或增大单点容量时须调整预算。
`HEAP_MEM_POOL_ADD_SIZE_DP_PARAMS` 覆盖参数副本和提交镜像。

公共 value_t 合并后默认固件静态 RAM 41,576 B、Flash 90,332 B；合并前为 41,576 B / 88,340 B。
点表初值和上下限使用完整联合体，增加只读 Flash；ARM 上运行数据大小不变。
增加的堆预算换取私有运行数据和更小的公共接口；链接结果不代表实板峰值。
UNIX 更新时间通过系统墙钟获取；未校时时不写入伪日期，也不额外分配 RTC 任务。

## 栈与验证

当前产品不创建 DP 样本/业务线程，DP 只在主线程和 Shell/故障上下文之外同步执行。
`CONFIG_MAIN_STACK_SIZE=4096`，`CONFIG_SYSTEM_WORKQUEUE_STACK_SIZE=2048`；
IAP 与看门狗任务使用各自栈。实板堆峰值和栈高水位仍需另行测量。

直接引用配置行后（2026-10-28），默认固件 Flash 为 90,080 B，静态 RAM 41,576 B。
删除临时 dp_point_cfg_t，不改变常驻点值大小及堆预算；未测量实板栈峰值。

登记时重复键检查临时申请每点 2 B 的 key 副本（24 点为 48 B），检查后释放，
随后才申请设备运行数据；增加点数时堆预算需分别覆盖这两个阶段的峰值。
排序在调用线程执行，所用栈取决于 C 库 qsort 实现。

key 副本排序检查后默认固件 Flash 为 91,564 B，静态 RAM 为 41,576 B；
C 库排序增加只读代码，原点表和常驻运行数据大小不变。

登记警告策略更新后，默认固件 Flash 91,764 B、静态 RAM 41,576 B。

删除 DP 只读权限后默认固件 Flash 91,732 B、静态 RAM 41,576 B。

回调后统一保存、配置与初值校验分离后，默认固件 Flash 91,660 B、静态 RAM 41,576 B。

初值直接复制内嵌联合体后，默认固件 Flash 91,540 B、静态 RAM 41,576 B。
