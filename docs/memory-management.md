# 当前内存与工作区

DP 的设备节点和全部点数据一次分配；配置行常驻只读。
当前 ARM value_t 32 B、dp_point_data_t 44 B（值、更新时间、已保存值指针、dirty及对齐），
设备头 24 B（含出厂恢复暂停状态），21 点基础申请 948 B；每个持久点额外分配 32 B 已保存值，有效标记平铺在点运行数据中。
产品三个持久点，因此共申请 1044 B，不含分配器开销；所有内容仍在同一次分配中。
普通 DI/AI 不分配保存副本。
登记重复 key 使用临时 OA/LP hashmap；21 key 扩容峰值约 1152 B，结束释放桶。
DP 默认堆贡献增为 4096 B；设备更多时需考虑已有节点及桶扩容峰值。
DP_HASH_LOOKUP 仍可选，仅索引 device_id，测点始终线性查找。

持久化固定存储描述包含管理 NVS 和按 CONFIG_DP_STORAGE_SLOT_COUNT 配置的槽位数组；
每 nvs_fs 含 NVS 自带缓存，默认 128 个 uint32_t 地址项，即每实例 512 B。
产品六槽加管理共七个实例；IAP 的独立 NVS 也因全局 cache 配置增加缓存。
保存线程栈默认 2048 B，记录编码仅使用栈上临时缓冲，不分配整表提交镜像。
设备锁保护生命周期/保存，点值锁仅保护 RAM 快照，不跨 Flash 操作。

2026-10-28 保存值替换前的构建基线：默认 IAPv3 应用 Flash 90,140 B、RAM 46,064 B；
--no-upload 应用 Flash 76,368 B、RAM 26,680 B；MCUboot 36,884 B / 18,096 B。
已保存值、挂载流程与槽位错误隔离调整后的默认应用 Flash 90,228 B、RAM 46,080 B；副本来自既有堆预算，
实际设备分配比替换前增加 96 B，副本占用既有堆预算；槽位独立错误标记使静态 RAM 比替换前增加 16 B。无上传数字仍为替换前基线。
当前默认应用堆为 DP 4096 B + IAP 12288 B + TRANSMIT 8192 B = 24576 B。
旧数值在下方历史章节保留，不代表新版本。
主机和模拟器不能证明实板峰值堆使用、Flash 耗时及栈高水位。

## 2026-10-31 转发接入

默认应用构建（复用官方 RAW）：Flash 103,692 B、RAM 65,464 B；MCUboot 36,884 B / 18,096 B。
新增 TRANSMIT 堆贡献 8192 B，总堆预算为 DP 4096 + IAP 12288 + TRANSMIT 8192 = 24576 B。
单转发实例申请实例头、256 个 uint64_t 接收时刻、256 接收字节和 256 发送字节，
不在请求期间申请内存。APP 另有 256 个带时刻的 ISR 队列项和 4096 B 协议线程栈。
启动峰值、持久参数保存和实际 UART 中断负载仍需实板测量。
RAW 复用前的自有分派基线为 Flash 96,508 B、RAM 62,768 B。
当前 MODBUS_NUMOF_RAW_ADU=1，增加接口会增加 Zephyr 的收发 ADU 及适配器 250 B 暂存；
默认 IAP 配置使每个 ADU 使用 MODBUS_BUFFER_SIZE=1100，按实际实例数配置 RAW 容量。
这些属于静态 RAM，不增加上面的系统堆预算。

# 工作缓冲区与系统堆

DP 登记时一次分配私有节点及该设备的全部点数据；应用只提供只读点表。
当前 `COMMON_VALUE_WORDS=16`，`value_t` 32 B，`dp_point_data_t` 36 B；
ARM 上私有节点头 16 B，本机 24 点一次申请 880 B（含头、不含堆开销）。
运行数据只保留点值和秒级更新时间。

参数直接使用设备点数据作为缓存；dp_init() 挂载前申请暂存值、已落盘值及提交镜像，
当前参数工作区为 2816 B。登记及参数工作区常驻到重启，不提供运行中注销。
失败不挂入设备目录，可重新登记；参数挂载错误由状态接口报告。

IAP 的位图、数据包、SGZ 与 Flash 写工作区由 `iap_init_config()` 一次申请，
失败时关闭 Flash 区域且不启动任务。SGZ/QuickLZ 纯算法接口仍由调用者提供工作区。

## 堆容量

所有模块共享同一个系统堆。`CONFIG_HEAP_MEM_POOL_SIZE` 为 0 时，Zephyr 使用
`HEAP_MEM_POOL_ADD_SIZE_*` 贡献之和：

| 配置后缀 | 当前预算（字节） |
| --- | ---: |
| `DATAPROCESS` | 2048 |
| `DP_PARAMS` | 4096 |
| `IAP` | 12288 |
| 合计 | 18432 |

2026-10-28 默认 MCUboot + IAPv3 构建系统堆为 18,524 B（含分配器开销）。IAP 预算覆盖
`receiver_buffers`：512 B 镜像写入缓冲、4.25 KiB 解包工作区、1 KiB 报文、
按容器位图约 4 KiB 及扇区位图 16 B。容器上限与板级暂存分区同为 512 KiB，
改任一项须同步 `CONFIG_IAP_MAX_CONTAINER_SIZE`。

`HEAP_MEM_POOL_ADD_SIZE_DATAPROCESS` 需要覆盖各设备节点头、点数乘以
`sizeof(dp_point_data_t)` 和分配器开销。新增设备或增大单点容量时须调整预算。
`HEAP_MEM_POOL_ADD_SIZE_DP_PARAMS` 覆盖参数副本和提交镜像。

公共 value_t 合并后默认固件静态 RAM 41,576 B、Flash 90,332 B；合并前为 41,576 B / 88,340 B。
点表初值和上下限使用完整联合体，增加只读 Flash；ARM 上运行数据大小不变。
增加的堆预算换取私有运行数据和更小的公共接口；链接结果不代表实板峰值。
UNIX 更新时间通过系统墙钟获取；未校时时不写入伪日期，也不额外分配 RTC 任务。

## 栈与验证

当前产品不创建 DP 样本/业务线程，DP 只在主线程和 Shell/故障上下文之外同步执行。
`CONFIG_MAIN_STACK_SIZE=4096`，`CONFIG_SYSTEM_WORKQUEUE_STACK_SIZE=2048`；
IAP 与看门狗任务使用各自栈。实板堆峰值和栈高水位仍需另行测量。

直接引用配置行后（2026-10-28），默认固件 Flash 为 90,080 B，静态 RAM 41,576 B。
删除临时 dp_point_cfg_t，不改变常驻点值大小及堆预算；未测量实板栈峰值。

登记时重复键检查临时申请每点 2 B 的 key 副本（24 点为 48 B），检查后释放，
随后才申请设备运行数据；增加点数时堆预算需分别覆盖这两个阶段的峰值。
排序在调用线程执行，所用栈取决于 C 库 qsort 实现。

key 副本排序检查后默认固件 Flash 为 91,564 B，静态 RAM 为 41,576 B；
C 库排序增加只读代码，原点表和常驻运行数据大小不变。
