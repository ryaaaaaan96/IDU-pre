# 工作缓冲区与系统堆

大块运行缓冲区使用 Zephyr `k_malloc()` / `k_free()`；配置点表继续使用
`static const` 常驻 Flash。线程栈、内核消息队列和固定 net_buf 池使用各自的
Zephyr 声明方式，设备索引及锁等小型控制状态保留原有存储方式。

| 工作区 | 申请与释放 |
| --- | --- |
| DP 点值和样本消费批次 | `dp_init_config()` 申请，服务生命周期内持有；初始化失败清理并允许重试 |
| DP 参数缓存、提交镜像与意图日志工作区 | `dp_params_init()` 申请；存储故障时仍保留缓存用于降级读取 |
| DP 处理事务、参考请求、发布批次 | 每次操作申请，成功或错误返回前释放 |
| 产品本地采样发布批次 | 首次发布申请一份，产品生命周期内复用；互斥覆盖映射至 zbus 复制完成，失败释放互斥，首次申请失败允许重试 |
| DP 异步业务队列 | 入队时申请副本，队列只传递指针；消费并完成回调后释放，队列满时立即释放 |
| DP 异步下发副本 | 后端完成前持有；超时后继续保留，迟到完成回调负责释放 |
| CO 队列及当前任务副本 | 仅在入队时申请；完成或取消的回调结束后释放，空槽位只保留指针 |
| CO 请求 ADU、采样批次及寄存器换算 | 每次调用申请；寄存器缓冲按实际数量申请 |
| CO/TR RAW 收发 | 接收 ADU 提交给 Zephyr 并复制后释放；发送按实际帧长申请，发送回调返回后释放 |
| TR 写请求与寄存器换算 | 每次请求申请，处理完成或拒绝时释放 |
| IAP 位图、数据包、SGZ 与 Flash 写工作区 | `iap_init_config()` 申请，服务生命周期内持有；分配失败关闭 Flash 区域且不启动任务 |

SGZ/QuickLZ 的纯算法接口仍由调用者提供大工作区，可以独立进行主机测试。
接收模块从系统堆申请这个工作区；不向算法内部增加 Zephyr 内核依赖。

## 堆容量

所有模块共享同一个系统堆，不划分模块独占的内存池。Zephyr 使用
`CONFIG_HEAP_MEM_POOL_SIZE` 与各 `HEAP_MEM_POOL_ADD_SIZE_*` 贡献之和的较大值
作为堆预算；贡献是容量预算，不是每个模块的硬隔离额度。

当前 IDU 的手动配置与模块缺省值合计为：

| 配置后缀 `HEAP_MEM_POOL_ADD_SIZE_*` | 当前预算（字节） |
| --- | ---: |
| `DATAPROCESS` | 256 |
| `DP_WORK` | 12288 |
| `DP_PARAMS` | 8192 |
| `COLLECT` | 8192 |
| `TRANSMIT` | 4096 |
| `IAP` | 16384 |
| 合计 | 49408 |

模块预算在各自 Kconfig 定义，产品可在 `.conf` 手动覆盖；不按固件类型自动
修改线程栈。新增设备、总线、队列深度、测点宽度或并发请求时，须重新核算常驻
申请、同时存活的临时申请以及分配器开销，不能只计算单个最大报文。

`k_malloc()` 不等待，申请失败返回 `NULL`。同步操作返回 `-ENOMEM`，不把内存不足
计作远端超时；RAW 接收失败仍释放接收忙状态。业务工作线程申请定时回调缓冲
失败时保留到期项等待下一轮；已入队任务直接交接其拥有的
堆对象，不需要消费端另行申请。故障请求不会清除其他请求的锁或端口归属。

## 栈与验证

此前 4096 B 采集栈在嵌套 ADU/RAW 缓冲下溢出，临时提高到 8192 B。
迁移后大缓冲不再叠加在线程栈上，`prj.conf` 将采集栈恢复为 4096 B，并保留
硬件栈保护。主机回归和 Arm 编译器栈报告用于检查分配、释放及代码占用；持续
实板通信、IAP 并发时的堆峰值和实际线程栈余量需要另行测量。

动态分配改变内存归属，不会让申请的 RAM 消失。固件 RAM 总占用包含系统堆
预留；本轮也移除了原有静态工作区，避免同时保留两份大缓冲。

本地样本路径不再逐次申请十个 `dp_point_update` 的映射数组，再经
`dp_submit_sig_values()` 申请完整批次；产品直接在复用批次中映射并调用
`dp_publish()`。以当前 16 字宽测点、12 点批次计算，消除同时存活的 440 B
映射数组以及每次中间复制；批次自身成为常驻共享堆用量，而非释放后可复用余量。
20 ms 发布预算覆盖工作区互斥及 DP 排队；成功仍只表示数据已复制接受。
普通 DP 字接口继续按调用申请，其他发布者不共用产品工作区。
`tests/points` 验证首次申请失败可重试、运行中本线程堆申请全部失败仍能发布正常
与失效样本；队列拥塞及质量测试继续有效。这不等同于实板并发峰值验证。
