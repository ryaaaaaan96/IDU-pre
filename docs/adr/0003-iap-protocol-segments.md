# 0003：IAPv3 使用设备挂载的协议地址段

状态：已接受，2026-10-21。替代 [ADR 0002](0002-process-point-callbacks.md)
第 5 项的全局完整 ADU 扩展选择；状态和命令回调的决定继续有效。

2026-10-22：[ADR 0006](0006-separate-forwarding-devices.md) 已接受将协议段改归独立虚拟转发设备配置，
替代下文的数据设备挂载选择；对应运行实现已完成。段匹配、变长报文、错误不回退和广播约定继续有效。

参考平台把 `MB_TABLE_SEG_T` 挂到设备的 `PRO_ADDR_SLAVE`，IAP 只是其中一个回调。
IDU 采用同样的三字段段表和设备关联，通过 Iterable Sections 保存在 Flash；
回调使用 Zephyr 完整 ADU，应用明确选择设备和广播策略，删除独立 `extension` 入口。

协议段按请求首地址匹配，优先于标准 PDU 校验；精确长度、功能码、变长载荷与会话
由回调校验。这样保留 1 KiB IAP 包，不放宽普通请求的限制。命中后的错误不回退，
重叠协议段在注册时拒绝。原有 `tr_segment` 仍用于标准寄存器范围处理和南向透传，
执行完整请求范围检查。协议段未命中才进入标准地址段及普通点表。

配置直接使用实际线地址，不复制参考平台隐式加一的规则；20049–20104 升级入口、
20003 能力和 31996–31997 版本入口沿用现有协议。只有显式开启 `route_broadcast`
才把广播交给协议段，普通点表广播继续静默且无副作用。TR 不依赖 IAP 或参数存储。
参考库未公开的匹配细节不被宣称兼容，IDU 以上述规则作为明确契约。
