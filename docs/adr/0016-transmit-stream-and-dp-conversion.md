# 0016：统一接收输入、锁定协议与 DP 整数转换

状态：accepted，2026-10-31；设计已确认；DP 类型转换、transmit/vport 及 APP Modbus 接入已实现；实板时序待验。

重新接入对外从机协议时采用 transmit、modbus、vport 三模块，APP 持有线程和物理接入。
以统一字节和事件输入支持内容判帧与时序判帧，transmit 持有缓存并按登记顺序锁定、
仅在解析不匹配时环形切换，接受首次匹配延迟以减少重复探测；有限期限和长度限制避免无限等待。
这取代 ADR 0014 删除通信后的能力范围选择，不直接恢复历史实现。

四个 DP key/index 读写接口增加显式输入/输出类型，由 DP 调用 common/value 完成整数转换，
避免协议侧重复配置和缓存内部类型；协议侧保留放缩、偏移及字序，业务回调使用内部类型。
该决定替代“内外类型必须一致”、DP 元信息查询及 transmit needs_conversion 的讨论提案，
实现后无类型读写入口已删除，应用和测试调用方均显式传类型。完整约束见[设计方案](../transmit-design.md)。

放缩配置统一使用 common 的 value_scale_t，转发表以 NULL 指针表示无放缩，不另设 flag；
最初约定计算类型作为协议点配置；该约定已由下文 2026-11-02 决定替代。

## 2026-10-31：复用官方 RAW 服务端

标准功能码、数量与载荷校验及响应构造改用 Zephyr modbus_raw_submit_rx 与官方服务端。
modbus 模块将第一次逐值回调转换为一次整笔访问，transmit 保留映射、预检、放缩和 DP。
采用按 RAW 槽位独立的回调上下文，不使用全局当前请求或跨实例执行锁。

原生 RAW 异步投递会改变业务执行线程，所以通过固定版本构建副本的受控钩子保留 APP 同步执行；
未占用接口继续默认异步。代价是需维护版本哈希及边界修复，实例数量受官方 1–4 限制。
当前产品仅配置 1 个 RAW 接口，避免 IAP 的大 ADU 配置放大未使用接口的静态 RAM。
RTU CRC/静默判帧与 IAP 路由不由 RAW 自动提供，IAP 上传仍未接入。

## 2026-11-02：统一采用对外类型

按用户确认，移除独立 calculation_type。读取先由 DP 转成 external_type，再放缩并按该类型编码；
写入逆放缩后也按 external_type 表示，再交给 DP 转为内部类型。
该决定简化映射配置，接受放缩前或逆放缩后的窄类型截断，读写不保证互为逆运算。
中间算术仍使用 int64_t 并检查溢出，不将数学配置与 DP 类型耦合。
