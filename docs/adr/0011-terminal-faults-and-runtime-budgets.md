# 0011：集中本地故障策略、交换预算与状态指示

状态：已接受。依据用户确认的 [Q1–Q10](../../.scratch/architecture-hardening/spec.md)；实现与验证见[验收记录](../../.scratch/architecture-hardening/validation.md)。实板验证另行记录。

## 决定

`app/status` 按故障来源选择构建期策略，保留首个故障的来源、阶段、错误和时间，以及最终终止来源和动作。动作是记录继续、停止业务留驻、复位；LED 运行期输出失败允许三种，指示灯初始化动作只允许留驻或复位；必需初始化、采样、发布、维护、镜像确认和登记任务超时仅允许后两种，默认复位。喂狗输出失败固定复位。

常规留驻保持外部看门狗正常输出；调试配置显式关闭看门狗，并使未显式配置的普通动作默认留驻；调用方明确请求的复位仍会执行。任务期限仍只覆盖显式登记项，本轮不新增产品任务登记。此决定替代 ADR 0009 中“任一任务超时必定复位”的固定动作，其登记、期限和 RAM 诊断契约继续有效。

终止时关闭 DP/CO 新业务准入，将 TR 转入休眠并拒绝共享线上的新北向请求，关闭 IAP 新请求。已开始的通信和 Flash 单元允许到安全边界；不挂起或中止持锁线程，不承诺撤销已执行下发。已准入的升级提交可完成 MCUboot 标记，留驻抑制后续自动复位；已提交标记不自动撤销。复位使用既有持久恢复规则。

南向每次 ADU 交换采用独立的 500 ms 总预算，覆盖总线、共享线、RAW、Zephyr 接口竞争、发送和响应；响应同时受原 100 ms 上限约束。自动重试重新计时，显式下发不自动重试。未发送的本地竞争超时返回 `-EBUSY`，不计远端无回复。业务排队、参数事务和多帧操作不合并为一个 500 ms 承诺。当前 115200/8N1、CO 最多 32 寄存器，最大标准读响应 69 字节；500 ms 为用户确认的初始预算，实板竞争余量仍待测。

本地样本复用一份互斥保护的共享堆批次，映射后直接发布到已有固定 zbus 池。首次分配失败可重试，后续发布不再分配本地临时数组或 DP 中间批次；发布失败仍是本地终止故障。

LED 使用 status 内的 delayable work，在已有系统工作队列直接调用 GPIO 接口；不新增线程栈。2026-10-24 按用户要求统一使用 GPIO，取代引入 LED 驱动的实现；设备树继续描述引脚和有效极性。启动和终止故障常亮，运行态标称 100 ms 翻转，允许普通调度抖动，不表示采样活性。初始化时仅检查和配置引脚一次；未就绪或配置失败立即报告终止故障并返回，禁止继续启动和采样；故障留驻时不访问未初始化的引脚。删除亮灭缓存和输出包装，迟到执行按错过周期的奇偶决定是否翻转，故障使用逻辑有效电平强制点亮。主循环只维护采样周期：超期即开始下一轮，不补采历史周期。

## 2026-10-24：故障上报接口简化

用户确认删除故障来源枚举和动作映射表。上报显式提供初始化／运行阶段、非零错误码、
英文常驻描述和最终动作；业务阶段继续保留用于编排，故障阶段只区分初始化与运行。
配置仍集中在 Kconfig，调用点传入配置值，status 不根据描述文本判断策略或改写调试动作。
指示灯初始化动作单独配置，只允许留驻或复位；初始化阶段提交继续动作会被拒绝。

首错描述、原因、阶段和时间不覆盖，当前终止描述及动作独立记录；重复终止动作幂等，
显式复位请求可将任何留驻升级为复位。此项替代先前仅按看门狗来源升级的规则。
描述保存指针，调用方须使用常量或常驻字符串，不做动态格式化和分配。
任务超时仍保留独立任务快照；不自动登记业务任务。验证见
[接口简化记录](../../.scratch/fault-interface/validation.md)。

## 验证边界与后果

真实协议 `init.c/tasks.c` 和主循环进入 native 测试，硬件边界采用 UART、Flash、GPIO/LED 和采样 adapter。停止标记直到复位不可清除，终止场景采用新进程验证。参数数据格式、远端离线和存储降级、任务归属、共享 RS485 的外部多主限制保持 ADR 0006–0010 的决定。

系统工作队列阻塞仍可推迟 LED；这符合普通抖动要求，不构成硬实时保证。共享堆容量不是模块隔离额度，复用工作区增加常驻持有、减少周期峰值；模拟故障注入不能替代实板堆峰值、栈余量、波形和复位验证。

## 2026-10-26：启动故障留驻

按用户要求，初始化失败改用 STATUS_ACTION_HOLD，避免固定故障造成软件循环复位。
包括输入、IAP、协议、指示灯、看门狗初始化，以及启动阶段任务超时和指示灯输出失败。
运行期故障仍明确复位。成功初始化的看门狗在留驻期间继续喂狗；初始化失败的
看门狗不再接受后台健康检查，避免将留驻误升级为复位。硬件自身无法喂狗时不能承诺留驻。
此决定替代上文产品调用点统一复位的规则。

## 2026-10-26：最近故障快照与直接动作

按用户要求取消首错保留与动作升级判断。每次上报覆盖最近故障快照并记录日志，
移除 terminal_description，不再依赖动作枚举的大小关系。继续只记录，留驻和复位
直接执行对应动作，重复请求也执行；停止接口支持重复调用。业务故障状态保持锁存，
后续继续动作只更新记录，不恢复业务。此决定替代此前首错锁存、终止描述及动作升级规则。

## 2026-10-27：停喂优先，日志与显示不阻塞故障处置

故障锁存后 RESET 先停外部喂狗，再关闭协议/IAP 准入，提交非阻塞延后日志并请求复位。
复位不等待日志后端、LED 或工作队列；仅测试钩子允许复位返回后继续提交显示与维护工作。
HOLD 保持外部喂狗，停止业务与任务监控。日志仍逐次提交，不增加应用日志缓冲队列；
LOG_MODE_DEFERRED 和关闭 LOG_BLOCK_IN_THREAD 为 status 的构建要求。

## 2026-10-27：监控自动处置与显式复位区分

监控故障通知改在 watchdog 的系统工作队列执行，硬件定时器在三倍检查周期有效期过后独立停喂。
显式 status_report_fault(RESET) 仍同步调用 watchdog_reset，底层 sys_reboot 由 watchdog 持有，不等待工作队列。
HOLD 显式关闭检查并保留喂狗；队列恢复不得清除已锁存监控故障。status 不再另设硬件错误轮询工作。

## 2026-10-27：故障上报统一归 watchdog

其他模块通过 watchdog_report_fault(error, description, action) 上报，移除公开 status_report_fault。
动作枚举归 watchdog，调用方不依赖 status，也不传整机阶段；status 根据自身状态判断阶段。
status_init 仍绑定唯一回调并启动 watchdog，不引入多订阅者或 main 故障入口。
status 的一个私有回调直接完成记录、状态更新和故障动作，不另设转调函数。
主动上报在调用者上下文同步通知，允许 ISR；回调返回值交给主动上报者，内部监控通知忽略返回值。
主动上报不覆盖监控锁存诊断、不改变健康有效期；CONTINUE 不停喂，终止后的 CONTINUE 不恢复业务。
此项替代前文调用点直接依赖 status 上报、显式提供阶段的接口约定。
