# 0011：集中本地故障策略、交换预算与状态指示

状态：已接受。依据用户确认的 [Q1–Q10](../../.scratch/architecture-hardening/spec.md)；实现与验证见[验收记录](../../.scratch/architecture-hardening/validation.md)。实板验证另行记录。

## 决定

`app/status` 按故障来源选择构建期策略，保留首个故障的来源、阶段、错误和时间，以及最终终止来源和动作。动作是记录继续、停止业务留驻、复位；LED 运行期输出失败允许三种，指示灯初始化动作只允许留驻或复位；必需初始化、采样、发布、维护、镜像确认和登记任务超时仅允许后两种，默认复位。喂狗输出失败固定复位。

常规留驻保持外部看门狗正常输出；调试配置显式关闭看门狗，并使未显式配置的普通动作默认留驻；调用方明确请求的复位仍会执行。任务期限仍只覆盖显式登记项，本轮不新增产品任务登记。此决定替代 ADR 0009 中“任一任务超时必定复位”的固定动作，其登记、期限和 RAM 诊断契约继续有效。

终止时关闭 DP/CO 新业务准入，将 TR 转入休眠并拒绝共享线上的新北向请求，关闭 IAP 新请求。已开始的通信和 Flash 单元允许到安全边界；不挂起或中止持锁线程，不承诺撤销已执行下发。已准入的升级提交可完成 MCUboot 标记，留驻抑制后续自动复位；已提交标记不自动撤销。复位使用既有持久恢复规则。

南向每次 ADU 交换采用独立的 500 ms 总预算，覆盖总线、共享线、RAW、Zephyr 接口竞争、发送和响应；响应同时受原 100 ms 上限约束。自动重试重新计时，显式下发不自动重试。未发送的本地竞争超时返回 `-EBUSY`，不计远端无回复。业务排队、参数事务和多帧操作不合并为一个 500 ms 承诺。当前 115200/8N1、CO 最多 32 寄存器，最大标准读响应 69 字节；500 ms 为用户确认的初始预算，实板竞争余量仍待测。

本地样本复用一份互斥保护的共享堆批次，映射后直接发布到已有固定 zbus 池。首次分配失败可重试，后续发布不再分配本地临时数组或 DP 中间批次；发布失败仍是本地终止故障。

LED 使用 status 内的 delayable work，在已有系统工作队列直接调用 GPIO 接口；不新增线程栈。2026-10-24 按用户要求统一使用 GPIO，取代引入 LED 驱动的实现；设备树继续描述引脚和有效极性。阶段到显示图案的映射集中在 `status_led.c` 的单张表：未初始化常灭、启动中亮/灭各 500 ms、运行态亮/灭各 100 ms、终止故障常亮；允许普通调度抖动，不表示采样活性。状态变化时提交立即刷新，迟到执行只跳到当前时刻之后的下一个边沿，不补放已错过的周期。初始化时仅检查和配置引脚一次；未就绪或配置失败立即报告终止故障并返回，禁止继续启动和采样；故障留驻时不访问未初始化的引脚。主循环只维护采样周期：超期即开始下一轮，不补采历史周期。

## 验证边界与后果

真实协议 `init.c/tasks.c` 和主循环进入 native 测试，硬件边界采用 UART、Flash、GPIO/LED 和采样 adapter。停止标记直到复位不可清除，终止场景采用新进程验证。参数数据格式、远端离线和存储降级、任务归属、共享 RS485 的外部多主限制保持 ADR 0006–0010 的决定。

## 定时器脱离任务监控共享锁

硬件定时器仅访问原子控制状态和 32 位健康截止时间，不读取 monitor、任务链表或共享诊断。先翻转 GPIO，再判断到期并锁存异常；故障原因、错误码及发生时间通过 Zephyr 消息队列交接。任务接口、查询和工作队列在原有锁内合并事件，通知仍由工作队列在锁外执行。健康续期不能清除已锁存异常，HOLD 保留喂狗但不能恢复 GPIO 失败；多核上已经进入 GPIO 的操作允许完成。

## 四参数故障上报与私有复位

统一入口为 watchdog_report_fault(error, description, action, uint32_t reset_delay_ms)。不再公开 watchdog_reset，HOLD 和 CONTINUE 忽略延时；最终动作为 RESET 时，0 立即复位，非零通过私有一次性 k_timer 延时复位。内部监控故障默认使用 200 ms。
业务上报和内部监控通知共用 handle_fault：先调用产品回调，再执行最终动作。回调只允许调整 action/reset_delay_ms，返回值仅作为上报结果。status 维护状态、关闭协议/IAP 并提交日志，不调用 stop/reset。故障查询保留上报方原始请求值。
（回调写回已由下文“故障回调只读与任务自登记”取代。）
延时期间停止任务检查但保留可用硬件喂狗；到期中断停喂后调用底层冷复位，不依赖系统工作队列。重复请求采用更早的期限，不能延后，0 可立即复位；相对定时器只需覆盖剩余时长，不依赖 CONFIG_TIMEOUT_64BIT，延时上限 60 秒，更长的请求按 60 秒提前。
此决定替代此前公开无参复位及 RESET 在故障回调内同步停喂复位的策略。延时仅提供日志处理机会，不保证打印或参数保存，不引入跨复位记录；GPIO 已失败或喂狗已停用时不恢复硬件，外部复位可能更早发生。

## 2026-10-27：故障回调只读与任务自登记

故障回调改为接收 `const struct watchdog_fault *`，只记录状态、停止业务、提交日志和刷新指示，不能修改快照，也不接收可写 decision 参数。
动作在进入 watchdog 时确定：主动上报使用调用方参数，内部监控故障由 watchdog 决定。
首个任务成功登记前，内部监控故障按 HOLD 处理；登记后按 RESET/200 ms 处理。不增加运行阶段接口，也不让通用模块依赖 watchdog。
主循环不是常驻监控对象，不登记自身；实际常驻任务由应用在任务入口登记，登记后内部监控故障按 RESET/200 ms，未登记任何任务时保持 HOLD。
此决定替代上文“回调允许调整 action/reset_delay_ms”的接口约定。

## 2026-10-27：简化 watchdog 控制与故障流

删除 registered 及按登记推断业务阶段的规则：内部监控故障统一 RESET/200 ms，初始化函数仍直接返回错误，应用可主动选择 HOLD。此决定替代上文任务登记前后不同故障动作的约定；只读回调、应用显式登记及不自动登记主循环的边界保持。
单一原子模式统一任务检查和喂狗许可，替代 initialized/stopped/checking/notified/reset_started 及 FEED_* 组合。GPIO 失败保持独立锁存，初始化尝试由一次性回调绑定判断。
只保留一份最近诊断。所有内部故障以只读快照入队，工作队列消费一次并通知/执行动作；查询仅查看，不触发状态更新或消费通知。序号只用于防止旧排队事件覆盖新的业务诊断，不参与控制。
线程和 ISR 的停止/复位共用同一条模式切换路径，已进入的 work 在非监控模式不再检查/续期。HOLD 不取消复位，STOPPED 不被 HOLD 重新启用；尚未投递的旧任务/CHECK 在显式 HOLD/RESET 后不再驱动动作，新的 GPIO 故障仍可通知并升级。

## 2026-10-27：LED 状态内部循环步骤

按用户要求，LED 指示状态与整机阶段分离，整机阶段到指示状态的选择由 status.c 负责，播放器不读取整机阶段。各 LED 状态对应静态亮灭/持续时长数组，一个 delayable work 循环推进步骤；同一状态不重启，切换到新状态从第一步开始，时长 0 保持电平并停止调度。工作队列延迟时逐步执行而不按绝对时刻跳过边沿，保证组合闪烁次数与顺序；此决定替代此前绝对相位追赶与等时闪烁模型。另提供快闪两次、慢闪一次及组间停顿的循环图案，不擅自增加业务告警判据。故障仍由 status 选择常亮，GPIO 故障策略保持。
