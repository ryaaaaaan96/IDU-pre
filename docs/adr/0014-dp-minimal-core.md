# ADR 0014：DP 最小原子核心

状态：已接受（2026-10-27）

## 背景

产品只运行本地 process：采集通过同步 `dp_set_sig_value()` 写入，转发、异步样本、
参数下游读回和参考表目录都不参与运行。原 DP 模块仍有五套初始化入口、
异步队列/线程、定时器、参考表和 collect/transmit 描述符，源码约 5,800 行，
链接文本约 18 KB，堆预算 20.7 KB。

## 决定

把 `modules/dataprocess` 收缩为最小原子核心：

1. 唯一入口 `dp_register_model(model, params_area)`：业务层逐组登记；每组校验后
   按实际字数申请自己的点值块。参数区在首次访问参数接口时挂载。
2. 只保留单点同步写读：`dp_set_sig_value()`、`dp_get_sig_value()`、`dp_read()`。
3. 点表行只解释常量、本地点、持久参数、范围、读回调和命令回调。
   命令点执行 `handler`，不保存触发值；状态点执行 `read`。
4. 参数只做本机 NVS：保留 `parameter_store.c` 的记录/提交镜像格式，
   删除下游转发、待确认意图、读回恢复和去抖业务线程。
5. 删除异步样本队列、业务线程、定时器、参考表目录、`data_process.h` 字节适配层、
   collect/transmit 描述符及相关测试。
6. 删除不再可用的 `modules/collect`、`modules/transmit`、`modules/vport`
   和旧应用通信装配。

## 结果

- DP 源码从约 5,800 行降到约 1,300 行；模块只剩 `points.c`、`params.c`、
  `parameter_store.c` 和 5 个头文件。
- 产品应用 Flash 从 106,100 B 降到 88,852 B，RAM 从 78,676 B 降到 40,728 B；
  系统堆从 45,404 B 降到 16,988 B。
- 点表、参数键和 NVS 记录格式保持不变；已有参数记录可继续读取。
- 设置项改为本机同步持久化，掉电恢复不再依赖南向读回。

## 后果与未决

- 采集/转发和 IAP 路由不再是本产品能力。`modules/iap` 仍保留 `iap_route()`，
  但当前没有调用者；重新启用通信需要新增独立的 Modbus/RAW 路由适配层。
  IAP 最小路由计划在下次调试 IAP 配置时实现，见
  [.scratch/iap-route](../../.scratch/iap-route/spec.md)。
- 参数宽度/类型变化会按格式不兼容清空 `idu-settings`，与旧行为一致。
- 实板参数持久化、掉电和 IAP 上传需单独验证；本轮只有主机/native_sim 证据。
- 历史 ADR 0006、0008、0010 记录当时方案，不代表当前能力。

## 2026-10-28：收敛点表接口

替代上述模型登记及并行读接口：使用 `dp_register(params_area)` 一次登记分区，
`dp_register_table(table)` 逐张登记点表；读写统一为 `dp_set_para()` / `dp_get_para()`。
`struct dp_model_cfg` 改为 `struct dp_table`。删除兼容头 model.h、公共 dp_read、
dp_stop/dp_stopped 及 DP 故障停止状态。status 锁存整机阶段，主循环停止业务；
DP 不参与整机故障策略。

保留参数恢复默认和状态查询；删除无实际刷新/重试行为的 flush/recover 及空的取消复位。
IAP 直接查询存储是否就绪。同步写已经落盘，无需第二次 flush。
删除原刷新/恢复事务命令点（31092、31093），访问时返回点不存在，不复用这些 ID。
NVS 记录类型编码、逻辑键和镜像格式不变。

## 2026-10-28：设备树直接绑定参数分区

删除 dp_register() 和运行时分区登记状态。DP 强制要求 `dp-params` 设备树别名，
指向启用的固定分区；缺失时编译失败。应用只调用 dp_register_table() 登记点表。
板级节点及 label 从 idu_settings / idu-settings 改为 dp_params / dp-params；
保留外部 Flash 偏移 0x10000、大小 0x4000 及 NVS 内容格式，改名不擦除存储。

## 2026-10-28：每张表持有点状态

以降低实现复杂度为优先，替代全局 slots/states 和点值堆分配：只读行定义仍由产品
提供，表描述改为可写并持有等长的独立 dp_point_state 数组，DP 挂接单向链表。
登记接口仍是 dp_register_table(table)，参数去掉 const；读写接口、回调、长度和
范围校验、本机参数持久化及 NVS 格式不变。登记须在线程启动阶段串行完成。

删除最大表数、最大点数、总字数预算和点值堆配置；参数数量和提交预算保留。
参数层枚举表链表并保存直接行引用，不再保存全局点下标。
每点预留完整值数组，使静态 RAM 略增，但去掉偏移计算、分配失败和跨表下标转换。
默认固件链接结果见内存管理；业务故障状态仍由 status 维护。

## 2026-10-28：只读表、私有设备目录与秒级更新时间

在用户确认后替代上一节的应用状态数组：公共 dp_table_t 只含只读行及数量，
设备 ID 由 dp_register_table(device_id, table) 入参指定。私有 dp_registered_table_t
展开保存描述字段，用柔性数组与运行数据一次分配；公共类型不暴露 next 或 data。
同表可用于多个设备。失败不发布节点，分配失败可重试。

DM_SIG_CFG_S 改为 dp_point_def_t，所有 DP 类型使用 dp_*_t 别名；字段统一
signal_id/size/flags/type/write/read。读回调只生成 dp_value_t，模块记录快照时间。
数值改为联合体，运行数据只保留 value 和 uint32_t updated_at_s。更新时间为 UNIX 秒，
默认、历史恢复及未校时记 0；不将 uptime 当作日期，超出 32 位范围记未知。
不引入 DP 授时接口，由系统 sys_clock_settime 设置墙钟，零墙钟偏移视为未校时。

参数共享设备点数据，删除第二份参数点缓存。参数 NVS 编码、哈希键和版本不变；
UNIX 时间不持久化。分配预算、结果及验证见内存管理和 .scratch/dp-private-registry/。

## 2026-10-28：明确业务回调名称

点定义和内部配置的 write/read 字段改为 write_callback/read_callback，类型改为
dp_write_callback_t/dp_read_callback_t。明确它们是业务回调，与 DP 自身的读写接口区分；
函数参数、返回值、执行顺序及保存行为不变。

点表字面值及内部解析配置中的 initial 同时改为 default_value，明确它是产品默认值，
不仅用于启动初始化，也用于恢复默认；只改名称，不改变数值或存储格式。

用户随后决定将 default_value 字段恢复为 initial（初始值）；回调命名保持不变。

## 2026-10-28：公共数值类型

将 dp_value_t 和 dp_default_value_t 合并为 modules/common/include/common/value.h 的 value_t。
容量由 COMMON_VALUE_WORDS 配置，其他模块不依赖 DP 即可使用。DP 继续通过点类型和长度
解释数据；大于四字节的点表初值仍使用 array 外部只读引用，运行值使用内嵌数组。
公共类型不定义编码、转换或持久化；DP 不因此新增浮点测点支持，NVS 格式保持不变。

点表配置类型同步由 dp_point_def_t 改为 dp_point_config_t，明确其配置用途，
与运行数据 dp_point_data_t 区分。

value_type_t 和 VALUE_TYPE_* 同时迁入 common。删除 dp_key_t，回调及内部函数
直接传 device_id、signal_id；参数键编码保持不变。

## 2026-10-28：区分 process 行索引与测点键

DP 配置、接口及回调中的 signal_id 统一改为 signal_key，数值及 NVS 编码不变。
process_signal_index_t 定义 process 行顺序，使用指定下标初始化点表。
DP 不保存 process 索引；业务通过行配置取得稳定键，避免顺序变化影响参数恢复。

## 2026-10-28：统一回调上下文

读写回调使用 dp_callback_t，接收只读 dp_callback_context_t：device_id、signal_key、
signal_index、可修改的 value 指针。索引直接取注册表的查找下标，不增加配置或持久字段。
读回调修改当前快照副本，成功且校验通过后更新点值；命令写回调可修改输入副本，
但维持只执行命令、不缓存值的语义。上下文和指针只在同步回调期间有效。

## 2026-10-28：直接引用配置行

删除 dp_point_cfg_t、dp_source_t 和 dp_describe_point 的重复解析层。
登记时校验 dp_point_config_t，运行时直接引用常驻只读行；初值按需展开，
范围直接使用公共类型及配置上下限。业务不得修改或释放行及其引用数据。
设备 ID 仍在设备目录；NVS 固定类型编码独立转换，记录格式不变。

## 2026-10-28：登记检查和标志简化

重复键检查改为临时 key 副本排序及相邻比较，保持原表行索引，不增加常驻索引。
删除 FLAG_READ_CALLBACK，非空 read_callback 即启用；其余标志改为 DP_POINT_FLAG_*，
类型为 dp_point_flags_t，保留原位值。回调增加 bool is_write 区分方向，不引入操作枚举。

## 2026-10-28：可忽略配置只警告

非数值类型的范围检查、非持久点的跳过恢复选项在登记时警告并忽略，
不修改只读配置；未启用的上下限静默忽略。影响数据解释及初值合法性的错误仍拒绝登记。

## 2026-10-28：写权限交给调用方

删除 DP_POINT_FLAG_READ_ONLY 及对应拒写和互斥校验。型号、版本等原常量配置
使用普通非持久点，可通过 DP 修改，重启恢复初值；协议或业务调用方控制写权限。
配置数组本身仍是常驻只读对象。参数键及 NVS 格式不变。

## 2026-10-28：回调后统一保存

允许持久参数配置读写回调。写回调先处理输入，读回调先取得已恢复的当前值；
回调完成后统一校验最终值，按 PERSISTENT 决定提交 NVS 或 RAM，读取提交成功再返回。
无读回调时保持纯读取。同值参数不重复写 Flash；失败不覆盖缓存和时间。
命令回调不再特殊跳过保存，产品恢复命令成功后主动清零。
回调副作用不回滚，同点并发回调不是原子读改写。

## 2026-10-28：直接设置内嵌初值

dp_initial_value 改为 dp_set_initial_value，直接复制 data.initial，不再调用 unpack。
点表数组初值统一内嵌 words/bytes；持久参数上电仍由参数层优先恢复 NVS 历史值。
函数也用于恢复默认，故名称使用初值而非仅限上电，不改变 SKIP_RESTORE 语义。

## 2026-10-28：参数加载归并

删除只复制初值的 dp_set_initial_value。登记及恢复默认直接赋值；参数层 dp_load_value
在挂载后读取历史记录，缺失时使用初值，错误向上传播。维持首次参数访问时统一挂载，
不在逐表登记期间提前挂载，避免禁止登记后续持久点。格式不兼容保留既有重置策略。

## 2026-10-28：先挂载、逐表加载

新增 dp_init()，只分配参数工作区、挂载及恢复提交日志，不枚举点表。
随后逐表登记，参数加载放在登记循环中，缺失参数整表批量提交后才发布设备。
读写及状态查询不触发挂载。失败回退本表目录并释放节点；提交失败冻结后续写入。
取消挂载后禁止新增持久点的限制，登记仍须在启动线程串行完成。
单点历史类型不兼容拒绝当前表并保留其他记录；挂载时日志格式不兼容沿用重置策略。

## 2026-10-28：减少锁的边界

移除独立 status_lock，状态与参数事务统一由 params_lock 保护；内部状态更新不再嵌套加锁。
启动 dp_init/登记为独占阶段，去掉启动锁，期间禁止并发所有 DP 操作，包括状态查询。
保留普通值快照锁，避免多字节点值撕裂；保留 NVS/工作区锁，防止事务相互覆盖。
状态查询可能等待 Flash 操作；回调继续在锁外执行。

## 2026-10-28：参数存储合并

parameter_store.c 合并进 params.c，删除 parameter_store.h 和独立构建项。
存储类型编码、记录定义及事务函数收为文件私有，直接使用唯一 NVS 实例。
合并单一调用方的缓存提交函数，移除恒真的保存判断及未使用的历史序号副本。
保留必要的记录校验、提交日志恢复及读历史重试，NVS 格式及逻辑键不变。

## 2026-10-28：先完成无参数持久化版本

按用户最新要求，删除 params.c、params.h、dp_init、持久化及跳过恢复标志，
删除产品恢复命令与存储状态点，DP 仅保留登记、RAM 写读、回调和范围检查。
登记直接设置初值，开始业务后使用一把快照锁；重启不恢复历史参数。
移除 DP 保存门禁及相应 IAP 配置选项，IAP 升级日志独立使用 NVS，CRC 配置保持不变。
原参数 Flash 分区和旧内容保留，不执行擦除或迁移。后续功能重新逐步增加。

## 2026-10-28：保留 RAM 恢复默认

按用户要求补回 DP_POINT_FLAG_SKIP_RESTORE 和 dp_restore_defaults(device_id)。
仅恢复目标设备未跳过点的 RAM 值及时间，不执行回调；初始化仍使用全部配置初值。
不恢复 Flash 持久化、初始化入口或产品命令点，继续共用唯一点值锁。

## 2026-10-28：精简无持久化核心

删除默认值占位宏和重复容量别名，产品点表省略零值及未启用的上下限。
单调用方 read_point 合并进读取接口，保留范围校验、编解码与共用保存路径。
私有校验不再重复检查调用方已保证的非空参数；公共接口仍检查非法输入。

## 2026-10-28：使用 Zephyr hashmap 检查重复键

用 OA/LP hashmap 作为临时 key 集合，删除复制 key、排序和比较函数。
插入返回 0 判定重复，负值返回错误，所有退出路径清空桶。分配使用 k_realloc 系统堆。
原表枚举行顺序不变，平均检查复杂度 O(n)，代价是桶和扩容峰值内存增加。
登记仍只在启动线程串行执行，不增加锁。512 行测试单独增大堆并覆盖分配失败清理。

## 2026-10-28：直接传递公共数值联合体

set/get 改为 value_t 指针，删除长度/容量参数和 pack/unpack，成功统一返回 0。
协议字节序归接入层，DP 不再使用固定小端字节编码；删除依赖字节布局的补位校验。
写回调处理输入副本，最终值校验后保存；读成功才更新调用方输出，失败保持输出不变。
应用 DI/AI 及采样周期直接使用 u16，测试替身使用相同签名，配置 size 仍决定类型长度。

## 2026-10-28：可选运行期 hashmap 索引

新增默认关闭的 DP_HASH_LOOKUP。关闭时设备线性查找；开启时仅 device_id 使用常驻 hashmap。
按用户进一步约定，设备内 signal_key 始终线性查找，不建立测点索引。
设备链表采用头插，不约定设备遍历顺序；测点数组仍按 process 枚举顺序，不排序。
登记失败释放节点，设备索引插入失败不发布；已有设备保持可用。
临时重复键集合继续独立使用，公共 value_t 接口和恢复默认语义不变。
两种模式默认堆贡献均为 2048 B；设备数量增加时需额外预算设备桶及扩容峰值。
