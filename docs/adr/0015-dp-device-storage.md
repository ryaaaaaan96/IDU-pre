# ADR 0015：按设备分区的 NVS 参数与延后保存

状态：已接受（2026-10-28）

## 背景

ADR 0014 最后阶段将 DP 收敛为 RAM 核心。用户现要求新增持久化，
每设备独立 NVS、每测点一条记录，内部划分总区域，设备可删除释放，五秒延后保存。
本决策替代 ADR 0014 的“无初始化、重启全部使用初值”和旧同步落盘语义。

## 决定

- register_table 改名 register_device，与 remove_device 对称；不保留旧兼容接口。
- 启用 DP 必须有参数分区，不提供单独持久化开关。
- 固定类型编码放入 common/value.h 的 value_storage_type()，模块间可复用。
- 增加 init 和阻塞 flush；保存使用单独线程，不使用 workqueue。
- points.c 管理运行点值，params.c 管理布局、槽位、NVS 和保存线程。
- 管理映射持久化，分配不依赖登记顺序；单点 NVS ID 使用稳定 signal_key。
- 固定首扇区布局标记用于挂载前识别未知数据；其余管理区和设备区分别挂载 NVS。
- 使用 NVS lookup cache；不维护易失效的 Flash 地址缓存。
- 回调后先更新 RAM，通过 dirty 和最后成功保存值的比较在后台落盘，失败留待重试。
- 删除先提交删除中标记，RAM 移除后擦除；启动完成中断删除。不自动回收未登记设备。
- 应用停止全部 DP 业务访问后才能登记/删除；设备锁使其与保存串行，点值锁不跨 Flash。
- 无记录使用初值；单点记录损坏/不兼容拒绝加载；总布局不匹配则清空参数区重建。

## 结果和限制

set/get 成功不再表示持久化完成；主动重启前需应用停止修改并 flush。
保存周期包含调度和 Flash 开销，掉电窗口不保证上限；恢复默认不具备多点事务。
旧参数和 IAP 地址保留，新 64 KiB 区域位于 0x1c000，六个设备槽位。
首次布局标记写入中断可在下次启动自动擦除重建，不引入额外双备份事务。
管理映射写入错误按槽位隔离，保留其设备归属，其他槽位可继续操作；重启核对真实落盘结果。

接口细节和配置以 [DP 模块](../../modules/dataprocess/README.md) 为准。
验证见 [.scratch/dp-device-storage](../../.scratch/dp-device-storage/spec.md)。

## 2026-10-28：以已保存值替代修改版本

按用户要求删除 revision。仅持久点分配已保存值副本和 valid 标记，运行点数据持有指针。
设备节点、运行数据和副本一次分配，移除时一次释放；Flash 记录格式不变。
保存成功后以快照更新副本，再与最新 RAM 比较 dirty，覆盖保存过程中 A→B→A 的情况。
按用户最新确认，登记主体收敛为两遍：第一遍校验配置及初值，同时统计持久点；
随后一次分配、挂载设备存储；第二遍设置初值、关联保存副本、加载及校验历史值。
数据结构、内存布局和锁保持不变，无效配置不会触发设备存储分配。

## 2026-10-28：映射错误改为槽位独立维护

删除全局 topology_error，每个槽位保存 mapping_error。提交错误时保留 device_id，
防止同槽位再次分配或同设备占用第二槽位；仅阻止该设备的挂载和删除。
记录未持久化与实际已持久化但返回错误两种情况，都在重启重新加载管理记录后确认。
布局/记录编码不变，不增加锁，已登记设备的普通读写和保存继续可用。

## 2026-10-28：配置持久设备容量

以 CONFIG_DP_STORAGE_SLOT_COUNT 替代槽位大小配置，默认六个槽位。
扣除布局/管理区域后，按数量均分完整扇区；每槽不足两个扇区时编译失败。
默认六槽仍为 8 KiB，既有布局编码和内容不变；改数量会改变布局，启动时自动清空重建；保留旧参数需另行迁移。

## 2026-10-29：保存指针与有效标记平铺

按用户要求删除 dp_saved_value_t，将 value_t *saved_value 和 bool saved_valid 平铺到
dp_point_data_t。仅持久点分配 value_t 副本，仍和设备节点一次分配、一次释放。
指针非空只代表已分配副本空间，saved_valid 才代表真实已保存记录。锁和 Flash 格式不变。

## 2026-10-29：布局不匹配自动重建

用户确认允许丢弃不兼容旧参数。删除空白扫描：读取布局头成功且不匹配时，
擦除整个 dp-params、写新布局头，再挂载管理 NVS。读取/几何检查错误直接返回，
不能当成格式不兼容；擦除或写头失败也直接返回。重试或下次启动继续建立布局。
单点记录错误不触发总区域擦除。旧参数保留区、IAP 及镜像区域不参与清理。

## 2026-10-29：管理映射非法自动重建一次

管理记录版本/长度/状态错误、设备 ID 为零或重复时，不再仅返回错误阻止启动。
打印非法记录槽位及原因，清空整个参数区并重建，再挂载/加载一次；仍非法则返回错误。
load_mappings 的 invalid 标记仅表示内容非法，NVS 读取返回的负错误码不触发清空。
完整映射校验成功后才执行未完成删除，不在检测到坏映射前按部分记录擦除设备槽位。

## 2026-10-29：区分默认值恢复与出厂恢复

SKIP_RESTORE 改为 SKIP_DEFAULTS，仅控制恢复默认值。新增 dp_factory_reset，删除目标设备
整个持久槽位（包括跳过默认恢复的点），保留 RAM 点表，锁外执行可选收尾回调后冷重启。
调用前由应用停止并等待全部 DP 业务访问结束；设备私有 factory_resetting 同时阻止保存和读写。
删除失败不回调、不重启，保持暂停供重试；已提交的删除在下次启动继续。无需额外出厂跳过标志。

## 2026-10-29：出厂恢复仅暂停 Flash 保存

替代上节停止业务访问的前置条件：出厂恢复不释放点表、不改 RAM 值，允许已有回调、
读写及默认恢复继续运行。factory_resetting 仅在设备锁内读写，控制 flush 跳过目标设备。
删除失败仍暂停 Flash 保存；成功锁外回调并冷重启。不需要调用计数或扩大普通读写锁范围。
恢复过程中仍不得并发登记/删除设备，保持配置行及设备节点生命周期稳定。

## 2026-10-29：保留全部设备选择值

DP_DEVICE_ID_ALL = 0，仅在出厂恢复中选择全部设备。设备锁内先禁止全部保存，再擦除整个
DP 总分区，包括布局、管理映射和未登记设备历史记录；成功锁外回调并重启，下次启动重建。
普通注册仍禁止 0；失败保持保存暂停并返回错误，RAM 读写继续，IAP 和镜像不参与擦除。

## 2026-10-29：合并存储删除入口

删除 remove_begin/remove_finish，dp_params_remove 直接写删除标记、擦除槽位、清理映射。
出厂恢复不再清理 storage 指针，保留 RAM 直至重启，禁止保存标志防止旧值写回。
普通 remove_device 复用完整存储删除，成功才释放 RAM；失败保留 RAM 并暂停保存，允许重试。
此顺序替代原先先释放 RAM 再擦除的方案，其他生命周期约束不变。

## 2026-10-29：统一单设备与全部删除

存储层只保留 dp_params_remove(device_id)，DP_DEVICE_ID_ALL 分支直接擦除总分区，
普通设备仍执行删除标记、槽位擦除和映射清理。移除 dp_params_erase_all。
调用方仍负责暂停目标保存；全部删除成功后必须重启，不继续使用原 NVS 挂载状态。

## 2026-10-29：保存失败失效副本与登记时修复参数

保存失败时旧副本不能再证明 Flash 内容，将 saved_valid 清零并保持 dirty，
后续写点、读回调或默认恢复不得通过旧副本取消保存；重试成功后恢复可信副本。
不增加版本字段、锁或运行数据。

替代原先缺失不保存、旧值不兼容/越界拒绝登记的策略：缺失记录使用初值并同步追加；
记录头不兼容或历史值越界时警告、回退初值并追加。负的存储读取错误除 -ENOENT 外
直接返回，不把 CRC/硬件故障当成配置不兼容。初值写入失败也拒绝发布设备，可重试。
登记不是整表事务，先前测点的追加可能已经成功，重试复用这些记录。

单设备出厂恢复仍要求已登记；上述配置变化不再阻止登记。真正读取故障不通过回退掩盖，
需要主动清除时可用 remove_device 删除未登记设备的历史槽位，再重新登记。

## 2026-10-29：允许未登记设备单独出厂恢复

取消 RAM 点表存在的前置条件。已登记设备先暂停保存，未登记设备直接清理历史槽位，
删除成功后锁外回调并重启；没有历史槽位同样视为成功。仍须先成功 dp_init。
删除错误不回调、不重启，允许重试，其他设备不受影响。
此决定替代上一节通过 remove_device 间接清理未登记设备的限制。

## 按 key 与 index 分别读写

原 dp_set_para/dp_get_para 拆为四个显式接口：dp_set_para_by_key、
dp_get_para_by_key、dp_set_para_by_index、dp_get_para_by_index。
index 为从零开始的点表行号，直接访问数组，不新增索引结构。
两种寻址方式共用回调、范围校验、RAM 更新及 dirty 处理；Flash 记录仍使用 signal_key。
