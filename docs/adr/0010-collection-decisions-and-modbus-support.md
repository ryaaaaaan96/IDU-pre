# 0010：集中采集决策并独立公共 Modbus 支持

状态：已实施，2026-10-24；完整套件分段验证及固件构建通过，未执行实板验证。见[讨论与验收](../../.scratch/architecture-deepening/discussion.md)。

采集状态与执行策略原来分散在 collect 的任务及状态实现中；将初始化推进、轮询期限、重试预算和离线恢复集中在内部决策实现，任务仍负责请求竞争、执行及等待。应用持有执行上下文和策略；以后 status 主动查询采集状态，首版不增加该调用。ADR 0007、0008 的行为约束继续有效。

CO/TR 原来重复 RTU 转换，collect 又跨目录引用 transmit 的公共兼容代码。新增应用自有 `modules/modbus`（Zephyr module 名 `modbus_support`）承接无分配 RTU 编解码、公共串口接入和必要的构建期兼容；转发扩展留在 transmit，通过可选钩子连接，公共模块不反向依赖 collect/transmit。这样增加一个公共依赖，以消除纯采集对转发目录的依赖及重复编解码知识；不重写 Zephyr 协议栈或向 vport 引入协议知识。

本决定取代旧的“公共兼容代码存放在 transmit 下”目录选择。事务身份、接收占用和完成规则仍归各自 RAW 适配；点表、存储格式、IAPv3 报文及应用物理口编排保持原语义。
