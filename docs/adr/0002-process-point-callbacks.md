# 0002：状态和命令归处理点表

- 状态：已接受
- 日期：2026-10-21

## 背景

参考工程在 `DM_SIG_CFG_S.pf_sig_proc` 中绑定设置/读取回调；IDU 原有
`tr_status_register` 和 `tr_command` 使状态和命令定义分散在 TR 服务配置中。
用户要求采用参考点表方式，读取回调按需触发，TR 保留地址段能力。

## 决定

1. 命令和状态加入 `tables/process.c`，回调实现在 `app/process/points.c`。
   `tables/transmit.c` 只维护寄存器到设备/信号的映射，不重复业务定义。
2. 普通设置为 `DP_PARA_SET`，初始化为 `DP_PARA_INIT`；配置
   `FLAG_READ_CALLBACK` 才在读取时调用 `DP_PARA_GET`。直接缓存读取接口保持原语义。
3. 32000–32003 合为一个四字数组点，每次 GET 只取一次参数状态，部分读取同样截取
   一份快照；状态拒绝写入。readback 回调与南向写后回读确认分开定义。
4. 31090–31093 保持地址、触发值和同步完成语义。设置回调使用新增的
   `dp_defer_para_action()` 登记动作；只允许单个本地非持久写点，在所有回调和范围
   校验完成后执行。允许读取其他点辅助校验，不允许其他/派生写入或混合完成动作。
   命令值不提交到缓存或 Flash；INIT/GET 不执行，不自动重试或重放。
5. TR 删除专用状态/命令结构；`tr_register_service.routes` 使用已有地址段路由。
   可选完整 ADU 扩展保留，以便 IAP 在标准 PDU 长度校验之前处理扩展帧。
   TR 注册服务不再依赖参数存储模块。
6. 不改变现有五个持久参数的键、类型、相对顺序及 Flash 分区，不引入 NVS schema 迁移。

## 结果与验证

业务绑定集中在 process 表。TR 只解释协议、映射地址并分发地址段；
DP 保证命令校验与执行顺序，命令返回成功时动作已完成。
这不使设备 I/O 具有跨请求回滚能力；失败仍通过原参数状态和恢复流程确认。

验证覆盖设置与读取时机、单字 FC16、拒绝混合命令和状态写入、状态快照、
校验失败不执行动作、执行失败不路由回退、持久化重启及 IAP 完整帧扩展。
桌面验证结果记录在[验证说明](../testing.md)，不代替实板掉电和总线时序验证。
