# 0008：南向离线按设备判定并降低轮询负载

状态：方向已接受，2026-10-22；初始化报错后恢复等细节讨论中，运行代码未实现。

用户确定南向按每台设备连续若干次轮询无回复判离线。离线后降低该设备的轮询频率，
本地采样、其他设备采集与北向转发服务继续运行；不因远端设备掉线停止整机喂狗。
通用判定和调度归 CO，策略由应用装配配置，状态由 protocol 接入 app/status。
北向离线检测暂不实现，留给后续应用协议编排。

按实际请求累计连续无回复，同一请求只更新一次最终计数；本地未发出的请求不计入。
有效异常应答也表示设备有回复，但操作错误须记录并可查询，通信状态不等于操作成功。
错误信息仅在 RAM 保存，由应用主动读取和清理，不因后续通信成功自动抹去历史错误。
初始化标记项与正常轮询项是两组；每次设备上线先执行一次初始化组，再进入正常轮询。
离线时只低频发送初始化组第一包；收到有效响应即恢复通信在线，立即继续其余初始化报文，
完成后才进入正常轮询。这样保留上线初始化顺序，通信在线与测点初始化完成分开表达。
初始化报文出错即停止后续初始化并报告错误，不跳过失败包进入正常轮询；报错后的恢复方式尚待确认。
有效异常应答代表通信仍在线，但不代表初始化成功。
失效测点保留旧缓存，北向读取返回协议异常；其他有效测点照常读取。
离线设备显式下发仍可尝试一次受超时限制的完整操作，持久事务与读回规则保留，
非持久命令不因重新上线自动重放。
