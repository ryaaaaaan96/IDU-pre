# 0007：应用协议层统一装配，初始化与任务调用分离

状态：职责、启动及故障边界已接受，2026-10-22；已按正式规格实现，验证见通信重构实施记录。

IDU 的 DP、采集、转发与参数恢复存在启动顺序依赖，原来分散在 main 和本地采样周期中。
用户确定由 app/protocol 统一编排，对 main 提供一个初始化入口；初始化与任务调用分开，
模块提供各自的初始化与任务调用能力，协议处理能力和端口在应用协议层组合。
这样由应用明确安排产品依赖，后续运行维护不再隐式承担首次装配和启动。

用户进一步确定由 protocol 在应用层显式创建并编排任务；模块提供回调注册接口，
由 protocol 注册以连接 CO 和 DP。协议解析的实现仍在可复用模块中，应用只组合协议处理能力、
点表和实际端口，不迁入通用解析实现。模块初始化不再隐式创建这部分执行任务或组合其他模块。

模块保留任务内部的等待、采集周期计算和调度逻辑，应用管理执行上下文。
站号来源由 protocol 初始化配置，可选择 DP 初始化后的数据读取或 GPIO 等方式。
CO 到 DP 的样本交付及 DP 到 CO 的下发/读回均显式注册，处理函数可以直接由模块导出，
无需强制应用再包一层转调函数。

统一初始化在本地装配阶段直接取得站号。取得方式由 protocol 决定，当前可静态写死；
DP/GPIO 等保留为初始化来源选择，不新增运行期等待地址、自动来源切换或回退框架。
运行状态按通信在线/离线表达，与本地初始化结果分开。
样本回调成功表示复制入队；参数下发/读回回调同步返回受超时约束的实际通信结果，保留既有事务完成语义。

南向按设备维护通信在线状态；模块报告状态、protocol 接入，app/status 决定 LED、健康和看门狗策略。
北向离线检测暂不实现，后续在 protocol 编排，不把主站长期静默直接认作本地系统故障。
南向离线与降频决定另见 [ADR 0008](0008-southbound-offline-polling.md)。

本地初始化完成配置检查、回调连接、参数加载/恢复处理和站号组装后，最后放行由 protocol 创建的任务。
远端初始化采集由任务执行，不阻塞本地初始化等待远端上线。IAP 路由开放前须满足其初始化前置条件。
参数存储不可用时报告故障但继续采样、采集和北向读取，需要持久化的写入失败；
IAP 保留参数保存失败时阻止升级提交/重启的约束。

实施验收依据见[正式规格](../../.scratch/communication-boundaries/spec.md)，快速阅读见[方案汇总](../communication-refactor.md)，
问答过程保存在[边界讨论](../../.scratch/communication-boundaries/discussion.md)。
具体接口与资源在后续实施中落实；规格发布本身不实施运行代码。ADR 0006 的数据设备与转发身份分离保持有效。

## 2026-10-27：暂时只运行 process

为先优化 process 的设计，用户要求暂时排除采集与转发，后续重新启用。
当前产品改由 `process_runtime.c` 绑定本地 process 表并启动 DP 线程，原通信实现原样保留但不参与产品构建。
本轮不改变通用 DP/CO/TR 接口，也不将通信处理迁入 process。
参数区暂不挂载，避免仅本地配置误判南向未决事务并触发格式清空；当前使用 RAM 默认值。
这是对本 ADR 完整装配流程的阶段性暂停，恢复步骤见 [protocol 说明](../../app/protocol/README.md)。

### process 同步运行，不创建 DP 线程

按用户进一步要求，当前入口移除 DP 样本和业务线程及其栈、创建和启动操作。
仅保留点表、数据池、处理计划和参考配置初始化；本地写点在调用线程内同步处理。
当前没有异步样本或异步业务生产者，也没有已登记定时业务；参数区仍不挂载。
通用处理函数及停用的旧通信线程实现保留，后续接回对应业务时重新确定执行上下文。
