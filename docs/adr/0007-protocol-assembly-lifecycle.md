# 0007：应用协议层统一装配，初始化与任务调用分离

状态：装配、任务归属和模块连接边界已接受，2026-10-22；具体接口契约讨论中，运行代码未迁移。

IDU 的 DP、采集、转发与参数恢复存在启动顺序依赖，目前分散在 main 和本地采样周期中。
用户确定由 app/protocol 统一编排，对 main 提供一个初始化入口；初始化与任务调用分开，
模块提供各自的初始化与任务调用能力，协议处理能力和端口在应用协议层组合。
这样由应用明确安排产品依赖，后续运行维护不再隐式承担首次装配和启动。

用户进一步确定由 protocol 在应用层显式创建并编排任务；模块提供回调注册接口，
由 protocol 注册以连接 CO 和 DP。协议解析的实现仍在可复用模块中，应用只组合协议处理能力、
点表和实际端口，不迁入通用解析实现。模块初始化不再隐式创建这部分执行任务或组合其他模块。

任务入口的运行模型、init 完成条件、站号输入、回调的数据/并发契约及故障策略仍待确认。
这些问题在[边界讨论](../../.scratch/communication-boundaries/discussion.md)继续讨论，
不得据此先行迁移运行代码。ADR 0006 的数据设备与转发身份分离保持有效。
