## 管理职责

`app/status` 统一编排任务监控、RAM 诊断、故障锁存及重启动作。
任务登记、心跳、永久休眠和超时检测均由应用层实现；仅复用 Zephyr 内核定时器和锁，GPIO 喂狗继续由底层模块执行。
任务通过 `status` 接口显式登记和报告进展；通用模块后续通过应用注册的健康回调接入，保持与产品头文件分离。

任务监控与故障策略共用 status 的运行阶段和状态锁；活动任务及超时记录由 status.c 的任务监控段 私有持有，不再维护独立硬件指针、超时回调或
初始化／终止标志。任务定时器静态初始化；登记前通过整机阶段、调试配置和底层
看门狗状态检查可用性。故障锁存时停止期限定时器，释放状态锁后再停止业务、停喂或复位。
任务超时快照同时阻止超时已经确定、故障处理尚未执行期间的迟到心跳和重新登记。

GPIO 喂狗周期与任务超时时间分别配置。任务期限由调用者在登记时传入，
活动任务通过调用者提供的常驻上下文串联，不预留固定通道、不分配堆内存，不需要任务看门狗功能或容量配置。
一个单次内核定时器跟踪最早到期项；登记、心跳、休眠后重新选择期限。无活动项时停止此定时器，外部 GPIO 喂狗仍继续。
每次重排需要遍历活动任务，开销随登记任务数线性增加；不为每个任务创建线程或定时器。
本轮不扫描线程，不维护应启动任务清单，也不检查登记遗漏。

## 喂狗规则

| 条件 | 外部喂狗与复位行为 |
| --- | --- |
| 没有活动登记项，且没有已锁存故障 | 持续喂外部看门狗。 |
| 活动登记项均在各自期限内 | 持续喂外部看门狗。 |
| 某任务显式进入监控永久休眠 | 仅取消该任务的超时计时，记录休眠标志。 |
| 任一活动登记项超时 | 锁存首个故障和任务身份，初始化阶段留驻，运行阶段停止外部喂狗并请求冷复位。 |
| 已锁存故障后登记项变成零 | 保持已选择的终止策略，不能通过删除或重新登记清除故障。 |

底层保持定期 GPIO 边沿输出；`status` 决定何时停止。
没有活动登记项时仍允许正常喂狗，因此旧主循环 1500 ms 进展超时和应用中隐式的 DP 活性检查，
不能继续作为未登记任务的看门狗约束。这些隐式监控路径已解除。
明确的本地故障按[故障策略](fault-policy.md)处理；普通留驻保持外部喂狗，喂狗输出失败固定复位。
远端设备离线保持 ADR 0008 的业务降级语义，不直接判定任务失去响应。

## 任务生命周期

```mermaid
stateDiagram-v2
    [*] --> Unregistered
    Unregistered --> Active: 显式登记成功
    Active --> Active: 按期报告进展
    Active --> Sleeping: 显式永久休眠
    Sleeping --> Active: 重新登记成功
    Active --> Fault: 超时
    Fault --> [*]: 按策略留驻或复位
```

登记成功即开始计时。正常运行中的重复登记返回错误，避免用登记操作代替心跳。
永久休眠保留明确标志，例如 `STATUS_TASK_SLEEP_FOREVER`；该状态的心跳不自动恢复监控，
必须重新登记，登记失败时保持未启用状态。
永久休眠只改变监控关系，任务自身的休眠、唤醒或退出由原业务编排。
已锁存超时后，永久休眠、迟到心跳或重新登记均不能撤销故障。

有限休眠继续计入时限：

```text
超时预算 ≥ 正常休眠时间 + 最长处理时间 + 调度余量
```

等待事件的工作线程后续采用有界等待，在处理或确认空闲后报告进展；
工作队列由同一队列执行健康探针。探针必须在被监控的执行上下文中运行。
长处理、NVS 操作、升级解包等允许时间由调用者预算覆盖，不增加自动延长期限或自动停用机制。

## 接口形态

`app/status/status.c` 提供能力，接口围绕显式登记、心跳、永久休眠和查询组织：

```c
status_register(&task, &config); /* 配置包含常驻名称和允许的最大心跳间隔。 */
status_feed(&task);
status_sleep_forever(&task);
status_register(&task, &config); /* 永久休眠后的恢复。 */
```

调用者持有常驻的任务上下文和名称，检查登记结果；活动链表及期限由 `status` 管理。
公开头文件为 `status/status.h`。任务配置包含 `name` 和 `timeout_ms`，
任务上下文只需零初始化一次，其字段由接口维护；配置值被复制，但名称必须保持有效。
登记状态直接由快照标志表示：0 为未登记，活动、永久休眠或故障均保留非零标志，
不再维护重复的登记布尔值。任务快照在状态锁内复制；物理后端错误在释放状态锁后查询。
`status_task_get()` 返回任务快照，`status_fault_get()` 返回首个故障及物理后端错误。
两种查询均不改变状态，也可在 ISR 中使用；没有相应记录时返回 `-ENOENT`。
登记、心跳与休眠成功调用限线程上下文；全局故障后返回 `-ECANCELED`，活动重复登记返回
`-EALREADY`，休眠或未登记对象的心跳返回 `-EACCES`。

不依赖 Zephyr Task Watchdog 子系统，产品与测试均不配置 `CONFIG_TASK_WDT*`。
应用构建始终包含此功能，软件复位依赖由产品 Kconfig 的 `REBOOT` 选择提供。
底层 GPIO 后端通过 `watchdog_error()` 查询状态，不再通过进展通知刷新单一主循环期限。

## 诊断与故障处理

RAM 中保存当前登记状态、任务名、期限、最后心跳、永久休眠标志和首个超时任务，提供查询。
普通 RAM 记录在重启后清空，不提供跨重启保存；故障路径不写 Flash。

应用内核定时器的超时回调运行在中断上下文，调用 ISR 安全的 `status_report_fault()` 锁存故障、设置业务准入门控并执行所选动作。
LED 操作交给已有工作队列，不等待其他任务、工作队列或日志落盘。
当前 GPIO 看门狗封装不是 Zephyr watchdog device，不通过原生硬件 watchdog fallback 接口接入。
复位策略先停喂，即使软件复位未完成也保持停喂；留驻策略取消任务期限但继续驱动外狗，物理喂狗错误会升级为复位。
保留 MCUboot 将 PC13 浮空禁用外狗、应用重新启用的板级交接。

## 本轮与后续接入

本轮提供按需监控能力，不给现有任务增加登记、心跳、健康探针或通用进展回调。
不新增任务就绪清单，也不把未登记任务加入镜像确认的额外条件；既有明确业务确认条件保持。

后续按用户需要逐项接入：主采样循环、DP 样本与业务处理、每条 CO 总线、TR 接收与配置队列，
以及启用 IAP 时的升级工作线程。Zephyr 内部线程暂不自动纳入。

## 实施验收

当前结果及命令见[应用层实现记录](../.scratch/task-watchdog/application-timer.md)。原三任务的[验收记录](../.scratch/task-watchdog/validation.md)和[两轴审查](../.scratch/task-watchdog/review.md)保留为迁移前证据。

- 零活动登记项持续喂狗；全部永久休眠时同样持续喂狗。
- 多任务独立期限互不代喂，任一超时按策略留驻或停喂及软件复位。
- 正常休眠和事件空闲不误报；迟到心跳不能恢复已锁存故障。
- 永久休眠标志、重新登记、重复登记、批量登记及无效参数符合约定。
- RAM 查询反映当前状态及首个故障；不产生跨重启存储记录。
- 现有任务保持未登记，不产生隐藏的主循环或 DP 任务超时约束。
- 区分主机/native 验证与实板 GPIO 波形、外部看门狗和复位链验证。

任务期限实现位于 `app/status/status.c`；不改动上游 Zephyr 或通用 GPIO 看门狗模块。
