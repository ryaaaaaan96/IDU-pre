# IDU-Transformer APP 总体设计

项目以 `IDU-Transmit.png` 为当前硬件图，产品与板级目标分别为
`IDU-Transformer`、`idu_transformer`。仓库根目录为 West 工作区，APP 位于
`product/app/`，板级位于 `product/boards/idu/idu_transformer/`，公共模块位于 `modules/`。
完整接线维护在 [pinout.csv](pinout.csv)。

## 硬件与业务装配

GD32E505VET7 使用 20 MHz bypass 输入，CPU 保持 180 MHz。
USART0 PA9/PA10 提供 115200 8N1 调试与 Shell。
三路 RS485 共用站号、点值和协议引擎，分别为 USART2 PD8/PD9 + PD10 DE、
USART5 PC6/PC7 + PC8 DE、USART1 PD5/PD6 + PB3 DE。
各路使用 UART async DMA，回复请求来源通道；IAPv3 仅允许 RS485-2。
SPI1 PB12–PB15 连接 GD25Q64，保留参数、升级暂存与日志分区。
PD11 为运行灯，PC13 为外部看门狗，每 10 ms 翻转。
SWD 使用 PA13/PA14，释放 JTAG。

原 I2C GPIO 扩展器及其配置已删除。DI1–DI10 全部来自 MCU GPIO：
PE2、PE3、PD12、PD13、PD14、PD15、PC9、PA8、PA11、PA12。
输入启用上拉，暂沿用低有效约定，实际极性需要实板确认。
每 500 ms 读取全部输入，成功后发布至 FC04 8153 bit0–9；有效为正常 0，
无效为异常 1，未使用高位为 0。8154、8155 已按新点表分配给风扇状态。
`inputs show` 直接读取输入用于诊断。

原六路独立 DO 及协议入口已删除。
A/B/C 是风扇反馈多路选择器的三个 DO，分别接 PE13/PE14/PE15，启动为 000。
采集线程每 100 ms 顺序选择 000–111，A 为最低位，完整一轮约 800 ms。
选择码与实际风扇编号的关系仍需核对；APP 在 `acquisition/fan_feedback.c` 的映射表中配置。

## 风扇 PWM 与反馈

风扇输出参考 IDU-pre 的 `modules/dev/fan` 和标准 Zephyr PWM 接口装配，固定频率 10 kHz，
初始化占空比 0%。上位机只设置占空比，0–1000 对应0–100%，精度0.1%。
`fan pwm <0..7> <0..1000>` 与协议调用同一控制入口，例如 `fan pwm 0 500` 设置50%。
频率固定，不再提供 Shell 改频率参数。同一定时器通道共用周期，逐路只更新占空比。

| 输出 | 引脚 | 定时器 |
| --- | --- | --- |
| FAN1 / FAN2 | PE5 / PE6 | TIMER8 CH0 / CH1 |
| FAN3–FAN6 | PA0–PA3 | TIMER4 CH0–CH3 |
| FAN7 | PE11 | TIMER0 CH1 全重映射 |
| FAN8 | PE12 | TIMER0 CH2N 全重映射，互补输出 |

FAN8 的 PE12 使用 GD32 平台模块补充的互补输出标志；驱动选择互补使能、极性和 PWM 模式，
保持占空比表示有效输出脉宽。输出定时器 TIMER0/4/8 使用180 MHz计数、预分频0，
10 kHz下每周期18000计数，0.1%对应18计数。捕获定时器 TIMER1 仍为1 MHz计数。SPI1、SPI2、TIMER8 的通用节点同样定义在 GD32 平台模块，板级仅配置接线。
风扇反馈公共输入 PB11 使用 TIMER1 CH3（PRMP2）硬件捕获，TIMER1 独占输入，
与 TIMER4 PWM 不冲突。计数频率为 1 MHz；GD32 驱动支持 CH0–CH3、16/32 位计数器、
通用定时器 global IRQ 与高级定时器 UP/CC IRQ，继续通过标准 Zephyr PWM capture API 接入。
设备树 `capture-prescaler` 默认 1，可改为 2、4、8；驱动归一化为单周期计数，
分频增大会增加测量所需边沿数量。旧 CH0/16 位捕获配置继续兼容。

反馈调度位于 `product/app/acquisition/fan_feedback.c`，由既有采集线程调用，
不新增 APP 风扇线程或系统工作队列任务。内部声明统一放 `acquisition_internal.h`。
每个 100 ms 时间槽结束时暂停捕获、收取最终快照，再切换到下一路；
风扇模块恢复前清除旧值，执行暂定 10 ms 的非阻塞稳定等待，然后开启单次完整周期捕获。
一槽有效捕获窗口约 90 ms，至少需要两个选定边沿；无完整周期时本路标为未就绪，
不沿用前一路或前一轮的结果。低速风扇及更高捕获分频可能无法在窗口内完成测量。
调度按固定时间轴推进，超期跳过、不连续补采；线程调度和其他采集会带来时间偏差。
停止采集时暂停捕获。通用风扇模块只对调用方返回整数 RPM，失败时不修改输出数值；
不再提供 `fan_speed_t` 诊断结构。采集范围独立于输出范围，由 `fan_feedback.c` 的 `channels[]`
逐行配置 MUX 地址、每转脉冲数、额定 RPM 和目标测点。`fan_feedback_acquire()` 收取一槽结果后，
执行 `反馈百分比 = 实测RPM × 1000 ÷ 额定RPM`，直接通过 DP set 写对应回传点。
APP 不再额外缓存八份数值，也不提供 `fan_feedback_get_speed()`；只维护点值有效性与采样时间。
每路额定 RPM 暂为0，表示等待实际参数，该点返回未就绪；每转脉冲数暂用2，需实板核对。
无完整周期、换算超过U16范围、额定转速未配置、数据超过2秒或采集停止时，读取返回异常，
不发布0冒充正常值；硬件选择、暂停或 DP 写入失败沿用采集终止策略。

输出控制位于 `fan_control/pwm.c`，点表控制回调位于 `dp_callbacks/fan_control.c`。
`fan show` 直接读取同一组回传测点，显示0.1%数值，不再通过采集私有接口取另一份快照。
风扇反馈 GET 回调仅校验有效性，不采样、不换算、不覆盖点值。

## PT100 温度采集

PT1–PT12 是 PT100 模拟前端输出，使用 ADC0 12 位原始采样，每路 500 ms。
映射分别为 PC0–PC3（CH10–13）、PA4–PA7（CH4–7）、PC4/PC5（CH14/15）、
PB0/PB1（CH8/9）。`pt show` 显示 PT1–PT20 最近一批成功采样的原始值与有效状态。
诊断输出先复制快照再打印，不在串口输出期间持有采集锁；整批任一路读取失败或采集停止即失效。
前端激励电流、放大增益、偏置及接线补偿未确认，当前不把 ADC 原始值当作温度发布。

SPI2 通过 PC10 SCK、PC11 MISO、PC12 MOSI、PA15 CS 连接 TPC5120S16-TS7R-S。
外部 ADC CH0–CH7 顺序对应 PT13–PT20，已接入与内部 ADC 相同的 500 ms 采集调度。
内部 12 路逐路读取，外部 8 路使用一次 ADC 序列读取；整批成功后统一更新原始值。
外部序列通道掩码为 CH0–CH7，初始化校验设备树映射与返回顺序一致。
芯片驱动位于 `modules/dev/tpc5120`，APP 通过标准 Zephyr ADC API 调用；
SPI 控制器继续使用 Zephyr 官方 GD32 驱动。板级设备树配置 Mode 0、1 MHz、
CS 建立/保持各 1 us，以及每路 `ADC_GAIN_1`（0～VREF）和外部参考。
此量程为当前软件配置，板上参考电压、前端输出范围和实板时序仍待确认。
驱动协议、流水线和通用接口限制维护在模块内，APP 不处理 SPI 命令和通道头。
依据 [3PEAK 官方数据手册](https://static.3peak.com/res/doc/ds/Datasheet_TPC512x.pdf) 完成实现；
按当前约定只记录原始值，温度换算位置保留在 `points_analog_read()`，
先返回数据未就绪，待补齐前端参数后再实现具体换算。
原电流、电压、NTC 点与校准参数已删除，温度点使用新地址 8181–8201，
类型 S16、单位 ℃、精度 0.1。温度21 暂无确定硬件输入；未获得有效温度时返回数据未就绪，
不以原始 ADC 值或初值冒充温度。

## 产品点表

[forward-points.csv](forward-points.csv) 与源码点表对应，Modbus 地址按表中原值使用，
不减一，U32 高字在前。内部信号键沿用产品规则，不采用用户表中的 signID。

| 寄存器区 | 地址 | 内容 |
| --- | --- | --- |
| FC04 | 8150 / 8151–8152 / 8153 | 设备类型 / 协议版本 / DI1–10 |
| FC04 | 8154 / 8155 | 风扇 DET / 通讯故障位图 |
| FC04 | 8156–8163 | 风扇1–8故障信息 |
| FC04 | 8164–8171 | 风扇1–8回传转速，单位 %，精度0.1 |
| FC04 | 8181–8201 | 温度1–21，单位 ℃，精度0.1 |
| FC03/06/16 | 8150–8157 | 风扇1–8 PWM设定，0–1000 对应0–100% |
| FC03/06/16 | 8158 | 风扇类型：0普通，1通讯 |
| FC03/06/16 | 30459 | 保留既有 Modbus unit ID 管理参数 |

转发表对 PWM 控制显式启用 SET/GET 回调，对反馈、温度和未实现状态点启用 GET 回调，
采集发布则不触发回调。PWM SET 回调直接调用风扇模块的千分比输出接口；GET 回读 APP 当前设定，
与 Shell 控制保持一致。默认 PWM 为0，风扇类型为0；这些控制点不持久化。
风扇百分比回传所需各路额定转速尚未提供，未配置的转速点返回异常；
故障编码与 DET 判据尚未提供，相关状态点返回异常，
不把默认0报成正常。通讯风扇协议尚未提供，当前设置类型1返回不支持。
整份清单共52个点（51个新业务点及1个既有站号管理点）。

## 启动、参数与故障

APP 初始化状态、看门狗、运行灯，初始化通信与 DP、IAP、采集与风扇后确认 MCUboot 镜像，
等待 10 秒进入运行状态。DI、PT 原始采集和风扇反馈由统一采集线程调度，按固定时间轴推进，
超期跳过历史周期。初始化失败锁存故障并留驻诊断；采集失败停止业务并申请延时 200 ms 复位。
运行灯启动阶段亮灭各 500 ms，运行阶段各 100 ms，故障锁存常亮。

参数成功写入只表示 RAM 更新，后台默认每 5 秒尝试保存。APP 主动重启前须停止修改并同步保存。
Modbus unit ID 保持寄存器为 30459，范围 1–246，默认 1，保存后重启生效。
旧模拟量校准参数及其保持寄存器 33000–33083 已删除，历史持久化记录不再加载。

## 内存基线与后续压缩

当前 MCUboot + IAPv3 构建的链接占用如下，后续代码或配置变更后应重新读取构建报告：

| 镜像 | RAM 占用 | Flash 占用 |
| --- | --- | --- |
| APP | 119760 B / 128 KiB（91.37%） | 137512 B / 457018 B（30.09%） |
| MCUboot | 19528 B / 128 KiB（14.90%） | 39572 B / 64 KiB（60.38%） |

APP 链接剩余 RAM 为11312 B，约11.0 KiB，余量较紧。链接占用已包含线程栈和系统堆预留，
不是运行时实际使用峰值；MCUboot 与 APP 分阶段运行，RAM 占用不相加。
系统堆配置合计约40 KiB，由 DP 8 KiB、通信20 KiB、IAP 12 KiB 的配置贡献组成，
实际为共享堆，不是三个独立分区。运行时堆内空闲量与链接剩余 RAM 分开统计。

后续安排内存压缩，当前先保留功能完整的配置。按以下顺序测量和调整：

1. 使用 `kernel heap`、`kernel thread stacks` 和 `protocol stats` 记录运行峰值，
   覆盖三路 RS485 并发、风扇与温度采集、参数保存、Shell 日志和 IAP 升级场景。
2. 优先核对通信线程栈（当前合计24 KiB）及其他线程栈，依据实测栈高水位逐项缩减并保留余量；
   同时评估风扇模块共用输入线程能否与现有采集调度整合。
3. 根据实际同时存活的分配量、最大申请块和升级峰值，调整系统堆预算与通信缓冲区、队列容量；
   不只依据空闲运行状态的剩余量缩减。
4. 评估量产配置中 Shell、调试命令和日志的保留范围，分别记录调试配置与量产配置的占用。

每轮调整后对比链接报告及运行峰值，重新验证通信并发、采集周期、参数保存与升级，
确认无分配失败、栈溢出或业务退化。主机检查和构建通过不能替代实板内存压力验证。

## 构建与验证

从工作区根运行 `./scripts/build.sh --pristine always`，默认 MCUboot + IAPv3；
`--no-upload` 关闭接收器。默认导出到
`build/hex/IDU-Transformer/idu_transformer/mcuboot-iapv3/`。
签名密钥继续使用 `build/keys/IDU-pre-dev.pem`，更名不轮换密钥。
`bash tests/run.sh` 检查根目录工具与构建配置；调试与烧录入口为
`scripts/debug.sh`、`scripts/flash.sh`。

主机检查与固件构建不能代替实板验证。尚需验证 DI 极性、PWM 波形、FAN8 互补输出波形、
反馈选择码、反馈与 PWM 共存、PT100 换算精度、外部 ADC 时序、RS485 与 IAP 互通。

本次验证：`bash tests/run.sh` 的 18 项检查、调试工具的 4 项检查均通过；
MCUboot + IAPv3 pristine 构建和镜像签名校验通过。尚未烧录实板验证。

临时主机桩还验证了 CH3 寄存器与中断配置、32位回绕、过捕获错误、旧CH0/16位/八分频兼容、
100 ms轮询、无反馈、通道切换隔离、过期与超期跳过，以及 PWM 千分比设定和越界拒绝。
主机桩不验证实际 AFIO 路由、捕获波形与中断时序。

重构验证还覆盖采集直接发布百分比测点、协议映射的读写回调标志、PWM 固定10 kHz的占空比设定与回读、
无效/过期数据拒绝。百分比发布的主机桩使用临时额定转速6000 RPM，未将该测试参数写入产品配置。
