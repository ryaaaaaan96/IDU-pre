# Transmit 与 DP 类型转换设计

状态：已确认的设计，尚未实现。2026-10-31 更新。
当前仓库没有 transmit、vport 模块；现有 DP 接口也尚未增加类型参数。
本文描述后续实现约束，不代表已具备通信能力。

## 模块职责

| 部分 | 职责 |
| --- | --- |
| APP protocol/port.c | 创建和管理线程，物理接入、虚拟端口分发、CAN ID、分片重组、回复目标和发送互斥 |
| vport | 统一端口输入输出，传递字节块与接收事件，不解释协议或 CAN ID |
| transmit | 对外从机协议编排，接收缓存、协议锁定轮转、转发表、权限、放缩偏移和响应处理 |
| modbus | Modbus 自身判帧、RTU 编解码、CRC 及公共协议支持 |
| dataprocess | 点表和业务回调，整数类型转换、范围检查、RAM 值与持久化 |

transmit 主动调用 modbus；将来新增协议允许修改 transmit，暂不增加通用协议注册框架。
APP 线程保证同一逻辑链路串行，不同链路可以并行。transmit 和 vport 不创建线程或工作队列。
多个实例通过配置表登记，每个实例绑定虚拟端口，每类协议最多登记一个处理实例；
一个 Modbus 处理实例对应一个从机地址。多个从机使用多个 transmit 实例。
配置启动时登记，常驻只读，第一版不支持动态站号、波特率或转发表变更。

## 输入、判帧与锁定

统一接收字节块与事件，协议自行判断帧边界。字节块可只有一个字节，块边界不是报文边界。
APP 提供实际接收时间、空闲边界及接收错误；线程处理时间不能替代接收时序。
内容判帧协议按帧头、长度或结束符判帧，RTU 按实际接收静默边界判帧。

transmit 持有未消费数据及边界记录，协议借用检查，不删除缓存、不执行业务。
检查结果区分等待、不匹配、完整有效；确认后才执行请求，执行完成消费对应帧。

1. 首次从登记的第一个协议开始锁定；等待时继续保留数据，不探测其他协议。
2. 完整有效则执行，消费报文后保持当前协议锁定。
3. 明确解析不匹配才按登记顺序环形切换，下一协议检查同一份未消费数据及已有事件。
4. 所有协议从共同起点检查，不自行搜索或跳过前缀。每轮每个协议最多尝试一次。
5. 全部失败后由 transmit 丢弃一个前缀字节，重新检查；保留真实边界，不能将 RTU 残片视为合法新帧。

每协议有最大报文长度及有限接收期限，无候选数据时不计时。
期限从候选数据原始接收时间计算，不随新字节无限延长，切换协议也不重启。
接手协议先检查现有数据是否完整有效，仍需等待且已超期才判定失败。
APP protocol 线程通过有期限的事件等待驱动超时推进，即使不再来字节也能结束等待。
接收丢字节、硬件错误或缓存溢出时清理受影响候选及解析状态，等待有效起点。
普通 CRC 不匹配仍采用轮转；业务错误不切换协议。

## 转发表与 Modbus 行为

入口配置表引用测点转发表；每行对应完整测点，配置寄存器类别、零基起始地址、
占用长度、device_id、signal_index、对外类型、字序与权限。
设备和 process 索引由应用枚举标识，协议地址与 DP 身份独立。
多寄存器默认高字在前，寄存器内部按 Modbus 大端编码；配置不要求按地址排序，
同一地址空间内禁止重叠。第一版覆盖功能码 01/02/03/04/05/06/15/16。

- 允许部分读取，读取同一转发行时只取值一次再截取；不同点仅保证逐点快照。
- 写入必须完整覆盖每个涉及测点，不做部分写入的读改写。
- 地址空洞整笔拒绝，不补零；执行前检查整个请求的覆盖、权限、长度及可预检转换。
- 多点写按地址顺序执行，首错停止，不回滚已完成业务；DP 回调及范围校验仍可能在执行中失败。
- 有效的其他站号报文静默消费并保持锁定；广播写执行但不响应。
- APP 分发广播至多个实例时，各实例独立执行；不提供跨实例去重。

## DP 显式类型接口（计划）

四个接口统一显式声明调用值的类型，不增加自动类型或旧接口兼容入口：

```c
int dp_set_para_by_key(uint16_t device_id, uint16_t signal_key,
                       value_type_t input_type, const value_t *value);
int dp_get_para_by_key(uint16_t device_id, uint16_t signal_key,
                       value_type_t output_type, value_t *value);
int dp_set_para_by_index(uint16_t device_id, size_t signal_index,
                         value_type_t input_type, const value_t *value);
int dp_get_para_by_index(uint16_t device_id, size_t signal_index,
                         value_type_t output_type, value_t *value);
```

SET：按 input_type 解释输入 → 转成点表内部类型 → 写回调 → 范围检查 → 更新 RAM/dirty。
GET：原有内部读取、读回调和校验更新流程 → 转成 output_type → 输出。
回调始终使用 DP 内部类型。GET 输出失败不修改调用方输出；回调已产生的副作用不回滚。
不支持的类型组合应在执行业务回调前拒绝。

第一版支持 U8/U16/S16/U32/S32 间整数转换；同类型复制，跨类型用一个私有函数、两个 switch：
按源类型读取到 int64_t，再按目标类型保存。转换输出联合体先清零。
缩窄保留低 N 位，有符号结果按目标位宽补码解释，不能依赖实现定义的越界有符号转换。
不做默认饱和；转换后仍遵守 DP 范围检查。字符串、字节数组和 WORDS 仅同类型访问，
不参与整数转换；不新增浮点自动转换能力。

transmit 不保存 DP 内部类型或 needs_conversion，不为此增加 DP 元信息查询接口。
类型是否一致由 DP 每次按接口类型与点表类型判断；原 key/index 查找方式不变。

## 放缩和偏移

放缩、偏移属于协议侧；DP 不接收倍率或协议字序配置。业务回调只在 DP 点表执行，
不恢复早期提议的 transmit 业务换算回调。

写：协议解码 → 协议放缩/偏移 → 带输入类型调用 DP → DP 收窄/扩宽 → 内部业务处理。
例如 U32 的 70000 先除以 100 得到 U32 的 700，再交给内部 U16 点，最终为 700。

读：请求足以容纳内部原值的 DP 输出类型 → 协议放缩/偏移 → 对外表示及字序编码。
不能先请求窄类型、丢失高位后才缩放；选用足够宽的整数作为协议计算中间值。
放缩配置的具体字段、舍入及计算溢出处理仍需在接口实现前收口，不据此引入浮点支持。

## 缓存与发送

每实例登记时一次分配固定收发缓存，失败清理，运行期不扩容或申请内存。
接收容量至少覆盖所有已登记协议的最大合法报文。
APP 发送回调同步且带超时，返回前完成或中止，不保留借用的发送缓存指针。
CAN 分片、UART 方向控制和共享物理口互斥由 APP 处理。

已执行业务的请求即使响应发送失败也消费，不重放业务、不自动重发、不解除锁定。
发送错误返回 APP。主站重试是新请求，不保证业务只执行一次。

位点/数组映射细节、错误到 Modbus 异常的映射，以及有限恢复工作量如何交还 APP 线程。

噪声恢复/溢出、广播/其他站号、地址权限/空洞/部分写、多点非事务错误、
整数截断/符号/输出不变、回调顺序、放缩先于收窄、发送失败不重放及实例隔离。
本轮仅文档一致性检查，无主机、模拟器或实板功能验证结论。
