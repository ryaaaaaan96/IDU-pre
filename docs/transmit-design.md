# Transmit 与 DP 类型转换设计

当前基线：Zephyr v4.5.0。
DP 显式类型接口、transmit/vport、Modbus 标准点表及 APP UART 接入已实现。
主机模拟串口和 IAP 完整 ADU 路由已验证；RS485 实板时序、负载及上传待验证。

## 模块职责

| 部分 | 职责 |
| --- | --- |
| APP protocol/protocol.c、rs485_1.c | 前者装配协议、管理线程及运行策略；后者提供 RS485-1 物理收发与字节事件，未来 CAN 路由仍归 APP |
| vport | 统一端口输入输出，传递字节块与接收事件，不解释协议或 CAN ID |
| transmit | 对外从机协议编排，接收缓存、协议锁定轮转、转发表、放缩偏移和响应处理 |
| modbus | RTU 判帧及编解码、Zephyr RAW 服务端、标准请求解析和响应、公共寄存器转换 |
| dataprocess | 点表和业务回调，调用通用类型转换、范围检查、RAM 值与持久化 |
| common/value | 公共数值类型、类型兼容判断与完整类型转换 |

transmit 主动调用 modbus；将来新增协议允许修改 transmit，暂不增加通用协议注册框架。
APP 线程保证同一逻辑链路串行，不同链路可以并行。transmit 和 vport 不创建线程或工作队列。
多个实例通过配置表登记，每个实例绑定虚拟端口，每类协议最多登记一个处理实例；
一个 Modbus 处理实例对应一个从机地址。多个从机使用多个 transmit 实例。
配置启动时登记，常驻只读，第一版不支持动态站号、波特率或转发表变更。
产品使用 APP 自有 idu,forward-port 绑定管理物理 UART；初始化 Zephyr RAW 服务端，不使用官方串口后端。

## 输入、判帧与锁定

统一接收字节块与事件，协议自行判断帧边界。字节块可只有一个字节，块边界不是报文边界。
APP 提供实际接收时间、空闲边界及接收错误；线程处理时间不能替代接收时序。
内容判帧协议按帧头、长度或结束符判帧，RTU 按实际接收静默边界判帧。

transmit 持有未消费数据及边界记录，协议借用检查，不删除缓存、不执行业务。
检查结果区分等待、不匹配、完整有效；确认后才执行请求，执行完成消费对应帧。

1. 首次从登记的第一个协议开始锁定；等待时继续保留数据，不探测其他协议。
2. 完整有效则执行，消费报文后保持当前协议锁定。
3. 明确解析不匹配才按登记顺序环形切换，下一协议检查同一份未消费数据及已有事件。
4. 所有协议从共同起点检查，不自行搜索或跳过前缀。每轮每个协议最多尝试一次。
5. 全部失败后由 transmit 丢弃一个前缀字节，重新检查；保留真实边界，不能将 RTU 残片视为合法新帧。

每协议有最大报文长度及有限接收期限，无候选数据时不计时。
期限从候选数据原始接收时间计算，不随新字节无限延长，切换协议也不重启。
接手协议先检查现有数据是否完整有效，仍需等待且已超期才判定失败。
APP protocol 线程通过有期限的事件等待驱动超时推进，即使不再来字节也能结束等待。
接收丢字节、硬件错误或缓存溢出时清理受影响候选及解析状态，等待有效起点。
普通 CRC 不匹配仍采用轮转；业务错误不切换协议。

## 转发表与 Modbus 行为

入口配置表引用测点转发表；每行对应完整测点，配置寄存器类别、零基起始地址、
占用长度、device_id、signal_index、对外类型与字序。
对象类别由 area 指定：线圈和保持寄存器读写，离散输入和输入寄存器只读；
不配置独立 access 权限，DP 校验与回调仍可拒绝写入。
设备和 process 索引由应用枚举标识，协议地址与 DP 身份独立。

tr_modbus_point_t 内嵌 tr_mapping_t：前者保存 area、address、count、word_order，
后者保存 device_id、signal_index、external_type、scale。
通用映射实现统一处理 DP 访问及放缩；Modbus 实现只处理地址与编码。
每行直接内嵌配置，无额外映射查找表或分配。后续协议可内嵌同一种通用映射。
应用入口仍为 transmit 的 tr_register()，内部映射读写函数不公开给应用。

多寄存器默认高字在前，寄存器内部按 Modbus 大端编码；配置不要求按地址排序，
同一地址空间内禁止重叠。第一版覆盖功能码 01/02/03/04/05/06/15/16。

- 允许部分读取，读取同一转发行时只取值一次再截取；不同点仅保证逐点快照。
- 写入必须完整覆盖每个涉及测点，不做部分写入的读改写。
- 地址空洞整笔拒绝，不补零；执行前检查整个请求的覆盖、对象类别、长度及可预检转换。
- 多点写按地址顺序执行，首错停止，不回滚已完成业务；DP 回调及范围校验仍可能在执行中失败。
- 有效的其他站号报文静默消费并保持锁定；广播写执行但不响应。
- APP 分发广播至多个实例时，各实例独立执行；不提供跨实例去重。

## Zephyr RAW 服务端实现

transmit 不自行分派功能码或构造标准响应，委托 modbus_support 的 mb_server_process 调用
官方 modbus_raw_submit_rx。官方按寄存器/位的回调由 modbus 模块转换为一次整笔访问，
transmit 做映射预检及 DP 操作，保留逐点快照和非事务失败行为。

原生 RAW 是异步投递；本项目使用固定版本、校验哈希的构建目录扩展，仅对自有接口同步执行，
业务仍归 APP 线程。modbus 模块不依赖 DP，独立测试禁用 DP/transmit。
RAW 接口由 Kconfig 预留，Zephyr 4.5.0 上限 4 个，当前产品用 1 个；并行实例不共享临时业务上下文。
CRC 与 RTU 帧边界不属于 RAW 输入能力，仍由前面的接收时序与 RTU 适配处理。

## DP 显式类型接口（已实现）

四个接口统一显式声明调用值的类型，不增加自动类型或旧接口兼容入口：

```c
int dp_set_para_by_key(uint16_t device_id, uint16_t signal_key,
                       value_type_t input_type, const value_t *value);
int dp_get_para_by_key(uint16_t device_id, uint16_t signal_key,
                       value_type_t output_type, value_t *value);
int dp_set_para_by_index(uint16_t device_id, size_t signal_index,
                         value_type_t input_type, const value_t *value);
int dp_get_para_by_index(uint16_t device_id, size_t signal_index,
                         value_type_t output_type, value_t *value);
```

SET：按 input_type 解释输入 → 转成点表内部类型 → 写回调 → 范围检查 → 更新 RAM/dirty。
GET：原有内部读取、读回调和校验更新流程 → 转成 output_type → 输出。
回调始终使用 DP 内部类型。GET 输出失败不修改调用方输出；回调已产生的副作用不回滚。
不支持的类型组合应在执行业务回调前拒绝。

第一版支持 U8/U16/S16/U32/S32 间整数转换；同类型复制，跨类型通过 common 的 value_convert 完成：
按源类型读取到 int64_t，再按目标类型保存；兼容判断和转换实现均位于 common/src/value.c，DP 只调用公共接口。转换输出联合体先清零。
缩窄保留低 N 位，有符号结果按目标位宽补码解释，不能依赖实现定义的越界有符号转换。
不做默认饱和；转换后仍遵守 DP 范围检查。字符串、字节数组和 WORDS 仅同类型访问，
不参与整数转换；不新增浮点自动转换能力。

transmit 不保存 DP 内部类型或 needs_conversion，不为此增加 DP 元信息查询接口。
类型是否一致由 DP 每次按接口类型与点表类型判断；原 key/index 查找方式不变。

## 放缩和偏移

放缩、偏移属于协议侧；DP 不接收倍率或协议字序配置。业务回调只在 DP 点表执行，
不恢复早期提议的 transmit 业务换算回调。

写：协议解码 → 逆放缩/偏移 → 按 external_type 表示 → 带该类型调用 DP → 内部业务处理。
例如 U32 的 70000 先除以 100 得到 U32 的 700，再交给内部 U16 点，最终为 700。

读：DP 原值 → 转成 external_type → 协议放缩/偏移 → 以 external_type 保存 → 字序编码。
按用户最新决定，读取先转换再放缩，替代之前先放缩后收窄的约定。
例如 U32 原值 100000，对外 U16、除以 100，结果为 344，不是 1000。
放缩前的截断与符号解释遵循 DP 类型转换规则；放缩后的结果同样按对外类型保留低位。
放缩由 common/scale.h 的 value_scale_t（分子、分母、偏移）描述；转发行引用只读指针，
NULL 直接跳过计算，不另设 flag。正向 output = input × numerator / denominator + offset，
写入执行逆换算；分子分母非零，除法向零舍入，中间 int64_t 运算溢出返回错误。
不配置独立计算类型；逆放缩结果同样按 external_type 保留低位，再交给 DP 转换为内部类型。
整数宽度转换仍归 DP；不新增浮点支持。未配置放缩时直接按 external_type 调用 DP。

## 缓存与发送

每实例登记时一次分配固定收发缓存，失败清理，运行期不扩容或申请内存。
接收容量至少覆盖所有已登记协议的最大合法报文。
APP 发送回调同步且带超时，返回前完成或中止，不保留借用的发送缓存指针。
CAN 分片、UART 方向控制和共享物理口互斥由 APP 处理。

已执行业务的请求即使响应发送失败也消费，不重放业务、不自动重发、不解除锁定。
发送错误返回 APP。主站重试是新请求，不保证业务只执行一次。

## 实现细节与验证

事件定义见 vport.h，at_us 为单调微秒；DATA 指针仅在输入调用期间借用。
transmit 为每个接收字节保存时间戳以恢复已接收的间隔，收到 POLL 时按时序推进 RTU 边界。
CUSTOM 的检查和执行通过固定配置回调接入；当前内容判帧测试协议不依赖 RTU 边界。
未来新增时序协议时需实现各自时序规则，不直接复用 RTU 判定为其协议规范。

数组每行 count 为寄存器数，WORDS 按 words 编码，BYTES/STRING 按原始字节编码；
位点行映射整数低 count 位。完整约束、异常码及缓存占用见
[transmit 契约](../modules/func/transmit/README.md)。固定接收容量限制每次恢复的最大数据量。

验证包括拆帧/多帧、RTU 间隔、锁定环形轮转、噪声及损坏恢复、广播、其他站号、
地址/对象类别/部分写、非事务失败、读取先转换后放缩及写入先逆放缩后收窄、发送失败不重放及模拟 UART 方向控制。
当前专项结果见[验证说明](testing.md)。
实板行为单独验收，不由主机或模拟器结果推定。

## IAPv3 完整 ADU 路由补充

保留普通 DP 映射，新增 tr_modbus_route_t 起始地址段表。RTU 校验与站号过滤后，
先把命中地址段的完整 ADU 同步交给回调，未命中才进入标准 RAW 服务端。
这样保留旧版超长 FC16 的 16 位寄存器计数及截断字节计数；IAP 自行严格检查载荷。
地址段只代表起始地址归属，不套用普通寄存器访问长度和数据区规则。
具体契约见 [transmit 模块](../modules/func/transmit/README.md)，地址见[产品协议](../app/protocol/README.md)。
