# IAPv3 地址段回调迁移方案

Status: proposed

## 目标和现状

按用户要求对齐参考项目的地址段表设计，将 IAPv3 从全局 `extension`
迁入设备挂载的协议地址段回调。普通状态和命令继续在 process 表处理。
现有 `tr_segment` 支持标准请求的地址段处理，但会先执行标准 FC16
长度限制与完整寄存器范围检查，不能直接承接现用 1 KiB 升级包。

  `app/iapv3/iapv3_commup.h:15–16` 的线地址为 `20049–20103`。
  实际地址换算的执行代码在闭源库中。

## 建议的明确规则（待用户确认）

1. 增加与参考工程同名、同三字段的 `MB_TABLE_SEG_T`，使用 Zephyr/C 类型。
   回调参数使用现有完整 `modbus_adu` 请求/响应，不引入 ARC 或旧解析结构。
2. 段表保存为 `static const`，沿用 Iterable Sections 登记，使用
   `PRO_ADDR_SLAVE` 挂载到本地设备。普通转发表与协议段表分开，
   不恢复 extern 数组、包含 `.c` 或手工维护数量。
3. IDU 配置统一填写实际线地址，不引入参考平台的隐式加一。
   IAP 主段沿用当前入口 `20049–20104`，能力地址 `20003`、版本地址
   `31996–31997` 也显式登记到 IAP 回调。保留现有线协议的边界行为，
   不因参考项目表面数字不同而改变升级工具的访问地址。
4. 协议段按请求起始地址匹配；IAP 回调负责功能码、精确长度、载荷上限、
   会话归属和广播语义。普通寄存器与透传段继续执行标准长度、范围检查。
   段重叠在注册时拒绝；命中后的错误或静默结果不回退到普通点表。
5. TR 保留端口地址过滤和 ADU 缓冲上限检查，在标准 PDU 校验之前分派
   协议段。TR 不包含 IAP 固定地址或产品头文件。
6. 产品 IAP 配置从 `.extension = iap_route` 改为协议段表；收敛不再需要的
   extension 入口。IAP 继续使用原接收、Flash 暂存、验签和升级状态机。
   只有显式允许广播的服务才能把广播送到协议段；普通点表广播保持无副作用。

## 验收条件

- 设备挂载及段表登记校验覆盖缺表、错类型、重叠和非法区间。
- IAP 能力、版本、状态、登录与 1 KiB 数据包经实际 TR 分发入口验证。
- 无效长度和包号不改变状态；升级广播写静默执行，普通广播不执行业务写。
- 非目标单元地址不进入回调；段外请求仍走普通点表；命中错误不回退。
- IAP 关闭时不登记升级段，普通点表、参数存储和南向采集可独立使用。
- 执行相关 native_sim 回归与 IDU MCUboot/IAPv3 构建；实板验证单独记录。
