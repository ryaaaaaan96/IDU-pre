# 架构修复规格

状态：2026-10-24，五项修复范围及 Q1–Q10 已由用户确认；开始实施。

## 目标

修复本地终止故障收敛、真实协议装配测试、南向事务总等待预算、关键采样工作区与压力策略、LED 调度归属五项问题。
实施基线为 `b7f3e24`；审查时应用工作树干净。本轮保留现有模块职责和业务协议，按实际问题深化 module 的 implementation，减少调用方必须了解的 interface 知识。

## 现有约束

- 产品仅 IDU；点表、NVS 数据键与格式、IAPv3 线协议保持现有含义。
- ADR 0006 的数据设备与虚拟转发设备分离继续有效。
- ADR 0007 的任务归属继续有效：应用装配 DP/CO/TR 执行上下文，通用 module 提供处理入口。
- ADR 0008 的远端离线降频、逐点恢复、显式下发不重试与存储降级继续有效。
- ADR 0009 的任务监控采用显式登记，不为本轮自动增加登记项，不恢复隐式主循环/DP 活性监控。
- ADR 0010 的采集决策集中、公共 Modbus 支持及各自 RAW 事务归属继续有效。
- 保留当前共享 RS485 联调拓扑，不新增外部多主仲裁承诺。
- 保留共享系统堆；线程栈和容量由产品配置手动维护，实板余量另行测量。

## 事实基线

| 范围 | 已核实事实 | 尚不能据此宣称 |
| --- | --- | --- |
| 故障收敛 | `prj.conf` 默认关闭看门狗；`main` 在本地故障后返回，已启动的其他线程不会因此自动结束；失效样本发布也可能失败。 | 已发生特定实板事故，或所有故障都会返回旧缓存。 |
| 真实装配测试 | `acquisition` 使用真实启动逻辑但 mock 任务函数；`shared_rs485` 使用真实端口和配置，但通过夹具创建任务。 | 产品装配已被完整集成测试覆盖，或当前必然存在启动竞态。 |
| 等待预算 | 南向交换在总线锁、共享线锁及 RAW 事务锁使用无期限等待；响应超时不包含这些等待。 | 无期限等待必然死锁，或总调用时间就是响应超时。 |
| 资源压力 | 本地发布先申请映射数组，再由 DP 申请批次并复制到固定 zbus 池；发布错误会触发本地终止故障。 | 当前已堆耗尽、内存泄漏或碎片失效。 |
| LED | main 读取下一翻转时间并在采样后的等待段推进 LED，status 健康检查也更新 LED。 | 当前实板已超过某个尚未定义的抖动容差。 |

本次审查已排除正常周期样本必然等待 `process_lock` 的推断：当前产品正常周期点没有进入该路径所需的处理回调或参数属性。

## 实施前事实补充

- 北向已有 `tr_port_set_mode(..., TR_MODE_SLEEP)` 和前置 filter，可限制后续请求；它们不会撤销已经执行的参数下发、Flash 写入或 IAP 工作。故障策略必须区分新请求与在途操作，不能用挂起任意线程代替事务收敛。
- CO 的休眠设置遇到在途总线锁可能返回忙，`co_cancel()` 只取消排队请求；DP/IAP 没有统一停止入口。`dp_params_prepare_reboot()` 会先保存参数，不适合未经区分地用作无 I/O 的故障冻结。
- 调试禁用看门狗依赖 MCUboot 将 PC13 浮空，应用跳过初始化以保持该状态；普通本地故障当前只停喂狗，显式登记任务超时才直接请求软件复位。
- 真实 `init.c/tasks.c` 可沿现有 `shared_rs485` 的 UART emul、Flash simulator 和产品配置接入；启动失败场景需要独立进程，不能假设单次初始化可以重置重跑。该套件当前不包含 IAP 完整路径。
- 南向锁链还包含 Zephyr `iface_lock`。现有 CO 响应超时为 100 ms，RAW 发送超时独立为 3000 ms；公开读写/交换入口目前没有总期限参数，不能仅替换若干 `K_FOREVER` 就承诺端到端时限。
- 当前串口 115200、8N1；1100 字节自身线时约 95.49 ms，尚未计入静默、竞争或响应。1100 字节是 IAPv3 扩大的共用容量，当前标准 CO 单次最多 32 寄存器，最大读响应为 69 字节。
- 新增本地竞争超时必须区别于已发出请求的无回复；当前 `exchange` 对 `-ETIMEDOUT` 的分类会影响南向状态。显式命令不得因此自动重放。
- 本板 LED 为 GPIOA8，当前 LED/GPIO 实现可短时寄存器输出；采用定时器中断仍需解决 status 的并发及生命周期，并将可能阻塞的故障处理留给可等待上下文。不能把此结论推广为任意 LED 驱动均可中断调用。

## 留驻与在途操作（已确认）

- Q9：留驻时仅保留 Shell/日志，常规构建继续驱动正常的外部看门狗；喂狗输出失败只能复位。任务超时纳入可选留驻/复位、默认复位，并更新 ADR 0009 相应固定动作约定。
- Q10：终止故障拒绝新业务请求及新 IAP；留驻时允许在途通信/Flash 到安全结束点，避免挂起持锁线程；复位策略依靠既有持久恢复，不承诺撤销已执行命令，不自动撤销已提交 MCUboot 标记。

Q9/Q10 已接受。策略 implementation 需使用故障来源区分 LED、外部喂狗及镜像确认，不能仅使用共享的健康检查阶段或 errno 分类。
