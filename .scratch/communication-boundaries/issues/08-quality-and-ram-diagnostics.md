# 08：贯通掉线失效与 RAM 错误诊断

**What to build:** 设备掉线后，北向看到其采集点失效；重新上线后逐点恢复。
应用同时能够读取、清理 RAM 错误和统计，而不改变设备状态或触发通信。

依据[已接受规格](../spec.md)。依赖 07 提供真实的每设备状态及明确的最终请求结果。

## 验收条件

- [ ] 掉线状态经应用显式连接接入 DP，使该设备所有 CO 采集点通信失效并保留最后数值。
- [ ] 北向读取失效点返回协议异常，本地及其他设备的有效测点继续正常访问，不额外触发南向读。
- [ ] 重新上线不批量恢复质量，各点成功采样后分别恢复；已保存参数目标不删除、不被反馈覆盖。
- [ ] 模块按设备保留 RAM 最近错误和统计，应用可通过公开接口获取一致结果；成功通信不抹掉历史错误。
- [ ] 清理只清记录和统计，不改变设备状态、测点质量、控制计时或重试预算，不触发初始化、重放命令或发送报文。
- [ ] 模块报告状态和进度，应用协议层接入应用状态管理；远端掉线本身不停止整机喂狗。
- [ ] 不新增北向离线判断，不把有效 Modbus 异常应答或主站静默当作本地系统故障。
- [ ] 并发读取/清理不破坏诊断和采集流程，其他设备不受某设备清理操作影响。

## 验证要求

通过完整北向响应、DP 公共读取、设备状态和诊断接口验证掉线、逐点恢复及清理无副作用。
沿用共享 RS485 和应用健康夹具，分别证明远端故障与本地任务故障的处理边界。
