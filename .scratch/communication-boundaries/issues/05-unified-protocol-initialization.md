# 05：统一 protocol 本地初始化

**What to build:** 整机通过协议层的一个本地初始化入口完成配置、回调、端口、参数处理和站号装配，
最后统一放行应用创建的任务。远端缺失不阻止本地初始化成功及北向服务启动。

依据[已接受规格](../spec.md)。依赖三个模块的执行上下文迁移完成；03 已包含 01 的连接前置条件。

## 验收条件

- [x] 协议层统一安排 DP、CO、TR 的配置检查、端口组合及显式回调连接，整机入口不再重复这些内部步骤。
- [x] 参数后端先绑定，加载和未决恢复所需同步通信路径先就绪，再处理参数加载/恢复和站号设置。
- [x] 本地必要装配完成后最后放行任务；配置、注册或资源准备失败明确返回，不提前开放不完整服务。
- [x] 本地初始化不等待远端上线，不把所有远端事务恢复完成当作无限阻塞启动的条件。
- [x] 有界恢复操作的实际结果及未决状态仍可查询，不假报远端初始化成功或参数已提交。
- [x] IAP 路由开放前满足升级模块的初始化依赖；本次不扩大为 IAP 或硬件服务任务所有权迁移。
- [x] 本地采样循环只承担其采样与健康职责，通信首次启动和日常维护独立推进。
- [x] 通过同一协议装配场景验证正常启动、关键失败路径及远端无回复，不通过调用次数代替外部行为。

## 验证要求

复用应用启动与公开报文夹具，观察任务放行前后的服务行为、错误返回及远端缺失时的可用性。
保留应用状态管理对本地故障的决定权；存储不可用的专门降级矩阵由 09 完成。
