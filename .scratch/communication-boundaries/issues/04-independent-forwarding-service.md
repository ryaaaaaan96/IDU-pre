# 04：让北向服务独立于本地采样运行

**What to build:** 应用显式提供 TR 接收及维护执行上下文，在本地初始化时传入站号并完成服务装配。
即使本地采样循环尚未推进，北向请求和通信维护也能正常处理。

依据[已接受规格](../spec.md)。本任务使用现有 DP/CO 公共能力，不依赖两者执行上下文已经迁移。

## 验收条件

- [x] TR 初始化、绑定和运行维护分别表达，日常维护调用不再兼任首次查表、装配和启动。
- [x] 应用提供 TR 接收和维护所需执行上下文，包括现有自有重配置队列涉及的任务；模块不隐式创建这些任务。
- [x] 站号在本地初始化时由应用明确传入，不等待首次完整采样，也不继续要求每次拨码采样更新。
- [x] 本地采样暂停推进时，北向完整请求仍得到正确响应，运行维护和必要恢复仍可推进。
- [x] 各转发入口的读写映射和协议段隔离保持，IAP 路由开放前满足初始化前置条件。
- [x] RAW 收发、发送错误、完成通知和共享物理资源仲裁保持；不新增外部多主保证。
- [x] 当前调用者及相关测试同步迁移，保留可选适配构建，栈及容量仍由 .conf 手动配置。

## 验证要求

沿用 transmit、transmit_port、forwarding_devices 和共享 RS485 夹具。
通过真实报文响应及采样不推进时的服务行为证明解耦，不依赖私有工作队列查询。

## Answer

TR 接收/配置队列及周期维护归应用，首次初始化与维护分离。站号在初始化设置，采样只查询维护故障。
当前测试北向站号显式配置为 16，南向 1、2 不变。公开报文及 IAP 大载荷回归通过，详见[验证记录](../validation.md)。
