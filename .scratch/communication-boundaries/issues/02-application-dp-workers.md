# 02：由应用创建 DP 执行任务

**What to build:** 应用提供并放行 DP 样本处理和业务处理的执行上下文。
DP 初始化后不会自行启动工作，但任务放行后测点处理、业务回调和参数服务继续正常运行。

依据[已接受规格](../spec.md)。本任务可沿用尚未迁移的 CO/TR 生命周期，不依赖其回调边界变化。

## 验收条件

- [x] 应用创建并编排 DP 样本处理和业务处理所需执行上下文，模块提供相应初始化、绑定及任务处理能力。
- [x] 不保留模块内部自动创建或自动启动的 DP 自有处理线程；初始化与任务运行分开表达。
- [x] 放行任务前不执行业务处理；放行后样本复制、处理完成等待、业务完成通知等公开契约正常工作。
- [x] 设置/读取回调、初始化计划、业务定时器、延迟保存及参数操作维持原语义；不改变现有持久记录。
- [x] 模块保留队列等待和处理算法，不要求应用逐测点调度，也不接管 Zephyr 系统线程。
- [x] 栈大小和容量仍由模块 Kconfig 定义、由 .conf 手动赋值，不增加固件类型预设或未来资源预留。
- [x] 相关应用和测试消费者同步迁移，保留关闭业务处理等现用可选构建；中间提交可构建、可验证。

## 验证要求

沿用 pipeline、dataprocess、reference_dp 和 reference_services 的公开处理接口。
通过任务放行前后的可见输出、完成事件及参数行为验证，不以线程名字或私有队列布局作验收。
