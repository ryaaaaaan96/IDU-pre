# 06：实现初始化标记与连续寄存器组包

**What to build:** 采集配置显式区分上线初始化组和正常轮询组，模块按点表声明顺序组织报文，
将兼容的连续寄存器合并，并把收到的数据正确交付到各自测点。

依据[已接受规格](../spec.md)。依赖 01 的显式样本交付边界，以完整批量结果验证组合后的数据链路。

## 验收条件

- [ ] 初始化标记由 CO 解释，独立于 process 的 FLAG_COLLECT；零周期不再单独决定初始化资格。
- [ ] 现用产品初始化读显式标记，仅下发命令不进入初始化或周期读，正常轮询继续使用 uint16_t 毫秒周期。
- [ ] 按声明顺序，仅合并同设备、同功能码、同采集阶段且周期兼容的连续寄存器；不跨空洞、不自动重排。
- [ ] 超过协议、报文缓冲或 DP 批量容量时正确拆包，不拆半个测点，不越界或部分错误发布。
- [ ] 初始化首包身份稳定；无初始化组时直接正常轮询，并可确定第一包正常周期读供后续探测使用。
- [ ] 合并后的回复仍正确更新原设备/信号，不改变持久参数身份，不把组包实现迁入应用。
- [ ] 60000 和 65535 毫秒配置不截断，初始化与正常组的成功链路可通过完整报文验证。
- [ ] 当前生命周期及显式初始化调用仍可运行；掉线、重试和恢复调度由 07 完成。

## 验证要求

复用 table_registry、reference_config、collector 和 pipeline 的现有数据及报文入口。
用发送顺序、寄存器范围和 DP 公共读取验证合并、拆分及阶段边界。
