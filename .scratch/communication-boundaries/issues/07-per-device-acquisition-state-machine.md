# 07：实现每设备四状态调度

**What to build:** 每台采集设备独立推进初始化、正常轮询、答复异常和掉线状态，
按配置重试和探测。故障设备降低负载，其他设备及北向服务仍能推进。

依据[已接受规格](../spec.md)。依赖应用驱动的 CO 执行上下文及明确的初始化/周期报文组。

## 验收条件

- [x] 每设备显式配置自动采集额外重试次数、最大异常持续时间和掉线探测间隔，不新增固件类型预设。
- [x] 初始化成功完成后进入正常轮询；当前初始化请求无回复时连续尝试，耗尽预算直接掉线。
- [x] 初始化有效异常应答停止后续包、报错并间隔后重新尝试，不因此判通信掉线，不跳过失败包进入正常组。
- [x] 正常请求超时重试耗尽进入答复异常，仍按正常周期轮询；超过最长异常时间仍未恢复才掉线，重复失败不重置等待起点。
- [x] 尚未正式掉线时恢复有效响应直接回正常轮询，不重做初始化；有效异常响应与无回复明确区分。
- [x] 掉线按慢间隔探测约定首包；有初始化组时成功后接着后续包，无初始化组时恢复正常轮询。
- [x] 显式下发不自动重试，失败不触发答复异常状态；掉线本身不禁止显式尝试，原事务和读回语义保持。
- [x] 本地未发出的请求不计作设备无回复，错误归属或无效回复不假报恢复，同一实际请求只记录一次最终结果。
- [x] 两台同端口设备按各自策略运行，不以整条总线切换初始化状态阻塞其他设备；等待、重试和物理收发都有界。
- [x] 公开设备状态可观察上述转移；批量测点失效及历史诊断清理由 08 完成。

## 验证要求

在同一公开报文集成场景注入成功、有效异常、无回复及本地忙，记录发送次数、顺序及设备状态。
使用短测试周期和完成事件验证状态边界，不导出私有状态机或依赖产品级长时间等待。
