# 09：验证存储故障降级与 IAP 保护

**What to build:** 参数存储不可用时，IDU 仍启动采样、采集和北向读取，
但持久写明确失败，升级提交继续受保存参数失败保护。

依据[已接受规格](../spec.md)。依赖 05 的统一装配和任务放行路径，不需要等待新设备状态机完成。

## 验收条件

- [ ] 在真实协议装配场景注入参数存储故障，仍放行可用通信及采样，并向应用状态管理报告故障。
- [ ] 北向读取、本地采样和南向采集继续；需要持久保存的写入返回失败，不先假报成功。
- [ ] IAP 保留保存参数失败时阻止升级提交/重启的既有约束，不因普通通信可降级绕过保护。
- [ ] 原持久设置的意图日志、读回、批量提交和未决恢复语义不变，非持久命令不在重启或上线时重放。
- [ ] 使用独立进程 Flash 记录验证旧参数值仍能加载，不因生命周期或配置重构改变键、格式或主动清空保存值。
- [ ] 原有不兼容格式的重置及诊断策略保持，不将已有恢复行为误改为无条件忽略错误。
- [ ] 本任务不强制将存储降级设备视为升级或试运行确认已成功，应用现有健康保护继续有效。

## 验证要求

沿用参数记录、独立进程重启探针及 IAP 失败短路夹具，通过北向结果、保存值和实际提交/重启行为验收。
不以重新挂载同一进程的内存替代真实重启边界。
