# 协议层统一装配、显式任务编排与南向设备状态机

## Problem Statement

IDU 的采集、测点处理、参数恢复与北向转发存在顺序依赖，但当前启动和维护分散在整机启动、
本地采样循环及模块内部。模块会隐式创建线程或工作队列，采集初始化还隐式安装 DP 后端。
维护者难以只看产品协议配置就理解实际任务、模块连接及首次启动的时间。

南向设备当前缺少完整的初始化、异常等待和掉线探测过程。单次操作结果容易被当作设备在线状态，
不能表达“设备确实有回复，但返回错误或尚未完成初始化”。初始化组与正常轮询组的边界、
掉线时如何降低负载、缓存何时失效和恢复，也缺少统一的可验收约束。

用户希望应用明确组合协议、端口、点表和任务，模块各自承担通用能力；每台南向设备独立推进状态，
故障设备不会使其他设备、本地采样或北向服务停止。参数无法保存时，也必须区分通信可用与持久写入失败。

## Solution

由应用协议层统一装配 DP、CO、TR 与端口，对整机入口提供一个本地初始化调用。
应用显式创建并编排执行上下文，模块提供初始化、回调注册及任务处理能力，保留通用解析与调度实现。
本地初始化完成配置、连接、参数处理及站号设置后放行任务，不等待远端上线。

每台南向设备采用初始化、正常轮询、答复异常、掉线四状态。初始化组成功完成后进入正常轮询；
正常采集超时重试耗尽先进入答复异常，在该设备最长异常时间内仍未恢复通信才掉线。
初始化无回复且重试耗尽直接掉线；有效异常应答说明通信存在，但初始化失败须停止并报告。
掉线后低频探测首包，恢复时按是否曾正式掉线决定是否重新初始化。

北向普通读继续使用 DP 缓存。设备掉线时统一使其采集点失效，逐点成功采样后恢复有效。
显式下发不自动重试，保持参数事务与读回语义。错误留在 RAM，由应用读取和清理。
参数存储不可用时继续通信和采样，但需要持久化的写入明确失败，IAP 的保存失败保护保留。

## User Stories

1. 作为产品维护者，我希望从协议层配置理解全部通信关系，以便不再追踪分散的隐式启动调用。
2. 作为产品维护者，我希望整机入口只调用统一的协议初始化，以便明确本地装配的完成边界。
3. 作为产品维护者，我希望本地初始化不等待远端上线，以便缺少设备时仍能启动本地采样和北向服务。
4. 作为应用开发者，我希望显式创建并编排通信处理任务，以便掌握线程、工作队列及资源分配。
5. 作为应用开发者，我希望初始化与任务处理分开，以便周期服务不再悄悄完成首次启动。
6. 作为模块维护者，我希望模块保留协议解析、队列等待和采集调度，以便应用不用重复编写通用算法。
7. 作为模块维护者，我希望初始化不隐式创建自身执行任务，以便相同模块能被其他应用按需组合。
8. 作为应用开发者，我希望显式注册 CO 到 DP 的样本交付，以便模块之间的连接可见且可替换。
9. 作为应用开发者，我希望显式注册 DP 到 CO 的下发和读回，以便参数服务不依赖采集初始化的副作用。
10. 作为应用开发者，我希望直接注册模块提供的处理函数，以便不用维护只作转调的包装回调。
11. 作为采集维护者，我希望样本交付复制数据并异步入队，以便发送方返回后缓冲区可以安全复用。
12. 作为北向主站，我希望写完成表示实际操作结果，以便不会把仅入队误认为南向设置已完成。
13. 作为配置维护者，我希望在本地初始化时决定站号，以便通信启动不再依赖第一次完整采样。
14. 作为配置维护者，我希望当前可以静态指定站号，以便不引入暂时不需要的动态来源切换机制。
15. 作为配置维护者，我希望北向站号与南向站号保持独立，以便保留同线不同站号的测试方式。
16. 作为端口接入维护者，我希望实际收发编排留在应用、vport 保持通用，以便后续替换物理接入不改点表业务。
17. 作为采集维护者，我希望每台设备独立维护状态，以便同一端口的一个故障设备不会拖停其他设备。
18. 作为配置维护者，我希望显式标记上线初始化测点，以便不再仅依靠周期为零猜测采集阶段。
19. 作为设备使用者，我希望每次正式掉线后恢复都重新采集初始化组，以便取得本次上线所需的基础信息。
20. 作为采集维护者，我希望初始化完成后才进入正常轮询，以便不会跳过初始化失败继续采集。
21. 作为采集维护者，我希望初始化无回复时按配置连续尝试，以便短暂丢包有机会恢复。
22. 作为采集维护者，我希望初始化重试耗尽直接进入掉线，以便不会再额外等待正常期的异常宽限时间。
23. 作为设备使用者，我希望初始化的有效异常应答被记录且阻止后续初始化，以便发现配置或设备能力错误。
24. 作为设备使用者，我希望有回复的设备不会仅因 Modbus 异常码被判通信掉线，以便在线状态真实反映通信情况。
25. 作为配置维护者，我希望没有初始化测点的设备也能正常轮询，以便简单设备不必维护空的初始化配置。
26. 作为配置维护者，我希望组包顺序遵循点表声明，以便明确哪一包会用于掉线探测。
27. 作为协议维护者，我希望仅合并兼容的连续寄存器，以便组包不跨地址空洞或混合不同阶段和周期。
28. 作为协议维护者，我希望组包超过协议或缓冲容量时正确拆分，以便不产生超长请求或半个测点。
29. 作为配置维护者，我希望采集周期继续使用毫秒值，以便直接配置包括 60 秒在内的轮询间隔。
30. 作为采集维护者，我希望正常请求超时重试耗尽后先进入答复异常，以便不会因短时故障立即宣布设备掉线。
31. 作为采集维护者，我希望答复异常期间仍按正常周期轮询，以便及时发现通信恢复。
32. 作为配置维护者，我希望每台设备有独立的最长异常时间，以便适配不同设备的通信特性。
33. 作为设备使用者，我希望短暂异常恢复后直接回正常轮询，以便避免不必要的重复初始化。
34. 作为配置维护者，我希望每台设备显式配置掉线探测间隔，以便控制故障设备占用的报文量。
35. 作为采集维护者，我希望掉线时只发送初始化首包，以便降低负载且保留明确的恢复入口。
36. 作为采集维护者，我希望没有初始化组时用第一包正常读探测，以便复用同一套状态机。
37. 作为采集维护者，我希望探测首包成功后直接继续后续初始化包，以便不重复发送已完成的首包。
38. 作为采集维护者，我希望本地忙或请求未发出不计作设备无回复，以便避免错误地判定远端故障。
39. 作为运维人员，我希望每次实际请求只记录一次最终结果，以便诊断统计不会同时把一笔请求算作成功和失败。
40. 作为北向主站，我希望普通读取继续访问采集缓存，以便不会因为每次读取额外产生南向查询。
41. 作为北向主站，我希望失效测点返回明确异常，以便不会把旧缓存当作正常的新采样。
42. 作为设备使用者，我希望设备掉线后其采集点统一失效，以便尚未轮到失败的测点也不会继续被误认为有效。
43. 作为设备使用者，我希望重新上线后逐点成功采样才恢复有效，以便通信恢复不掩盖尚未刷新的数据。
44. 作为设备使用者，我希望掉线不删除参数目标，以便已保存设置不被采集反馈或通信状态覆盖。
45. 作为北向主站，我希望即使设备掉线也能显式尝试下发，以便获得当前实际操作结果。
46. 作为北向主站，我希望显式下发不自动重试，以便降低丢失应答时重复执行命令的风险。
47. 作为采集维护者，我希望显式下发失败不触发答复异常状态，以便设备状态仍由自动采集流程判断。
48. 作为设备使用者，我希望持久设置保留意图日志、读回和未决恢复，以便通信失败不破坏已确认的事务规则。
49. 作为设备使用者，我希望非持久命令不在重启或重新上线时自动重放，以便恢复流程不会再次触发操作。
50. 作为运维人员，我希望读取设备的错误记录和统计，以便在设备仍在线时也能看到操作错误。
51. 作为应用开发者，我希望主动清理 RAM 中的错误记录和统计，以便自行决定诊断信息的保留时机。
52. 作为设备使用者，我希望清理记录不改变状态和测点质量，以便清日志不会被误当作修复故障。
53. 作为设备使用者，我希望远端掉线不停止本地采样、其他设备采集或北向服务，以便局部故障不会影响整机可用性。
54. 作为产品维护者，我希望显示和看门狗策略仍由应用状态管理决定，以便模块不会替产品决定停机。
55. 作为设备使用者，我希望参数区故障时仍可采样和读取，以便持久存储故障不会阻断全部通信。
56. 作为北向主站，我希望需要保存的写入在存储不可用时明确失败，以便不会收到虚假的保存成功。
57. 作为升级维护者，我希望保存参数失败时继续阻止升级提交或重启，以便通信降级不会绕过 IAP 保护。
58. 作为配置维护者，我希望线程容量和栈大小继续手动设置，以便不为固件类型或未来接口自动预留资源。
59. 作为测试维护者，我希望从完整报文与公开查询验证行为，以便测试不依赖私有状态机和线程布局。
60. 作为产品维护者，我希望保留参数记录、现有业务回调及 IAPv3 线协议，以便重构不要求清空设备配置或修改升级工具。

## Implementation Decisions

1. **统一装配边界。** 应用协议层组合数据设备、虚拟转发入口、点表、协议角色、端口和执行上下文。
   DP、CO、TR 各自提供初始化、回调注册及任务处理能力。初始化、注册和运行处理分别表达，
   不再由 CO 初始化隐式安装 DP 后端，也不由 TR 日常维护入口首次完成装配。
2. **任务归应用。** 应用显式创建和编排 DP 样本处理、DP 业务处理、CO 采集以及 TR 接收/维护所需执行上下文。
   模块初始化不隐式创建这些线程或工作队列；模块仍负责内部等待、调度和协议状态机。
   不接管 Zephyr 内核或子系统线程，不要求各类任务具有相同入口形态，不将轮询算法迁入应用。
3. **本地启动契约。** 统一初始化先完成配置检查和必要资源准备，再装配模块、端口及双向回调，
   处理参数加载与未决恢复、取得站号，最后放行应用创建的任务。参数后端须在参数初始化前绑定，
   供恢复使用的同步通信路径须已就绪；远端不可达仍由既有恢复结果与设备状态表达，不能无限等待远端上线。
   IAP 路由开放前必须满足其初始化前置条件。本地配置或装配失败不得伪装成功或提前开放不完整服务。
4. **本地初始化与远端上线分开。** 统一初始化成功表示本地装配完成，不代表远端存在、初始化完成或所有测点有效。
   远端初始化采集由任务执行。北向启动、日常维护及运行恢复不再依赖本地采样循环调用。
5. **站号在初始化确定。** 由应用协议层选择来源，当前允许静态指定；DP 或 GPIO 可作为今后的初始化来源。
   不增加运行期等待站号、自动回退或动态来源切换。北向与南向站号分开，不把数据设备 ID 当作站号。
   本决定替代旧方案中北向必须由每次拨码采样更新的要求，不改变独立转发入口的身份和映射规则。
6. **显式双向连接。** CO 样本到 DP、DP 下发/读回到 CO 均通过公开注册接口连接。
   允许直接注册模块导出的通用处理函数，不强制应用包装。CO 的设备状态和质量变化也经明确连接接入 DP/应用状态管理，
   不能借批量失效功能恢复隐式模块装配或引入产品头文件依赖。
7. **回调完成与数据所有权。** 样本交付须复制后异步入队，成功仅表示接受；队列满或超时必须返回错误。
   下发/读回同步返回受超时约束的实际结果，持久写完成不能退化为“已入队”。回调上下文与配置的存储期覆盖运行期；
   接收者不得保留已失效的栈缓冲。不得在持有参数事务锁的回调中再次进入参数事务，或让同步操作等待其自身阻塞的队列。
8. **采集阶段显式标记。** CO 解释初始化标记，初始化组和正常轮询组分开；初始化标记与 process 的 FLAG_COLLECT 下发标记不同。
   每次正式上线执行一次初始化组，完成后才正常轮询。零周期本身不再足以判定初始化资格；
   产品现有初始化读要显式迁移标记，仅下发命令不能误变为初始化读或周期读。
   周期仍为 uint16_t 毫秒值，保留 60000 和 65535 的表达能力，不恢复周期编码转换。
9. **组包契约。** 按点表声明顺序，只合并同设备、同功能码、同采集阶段且周期兼容的连续寄存器。
   不跨地址空洞，不自动重排以改变首包身份。拆包同时遵守协议长度、报文缓冲及 DP 批量容量；
   不能拆出半个测点或因合并造成越界、部分错误发布。组包属于模块能力，应用不逐项拼装采集请求。
10. **无初始化组的设备。** 直接正常轮询；掉线探测使用该设备第一包正常周期读。
    有初始化组时只能使用初始化首包探测。首包成功后继续其余初始化包，不重复发送已成功首包。
11. **每设备策略。** 每台采集设备显式配置自动采集重试次数、最大异常持续时间和掉线探测间隔。
    初始化与正常轮询共用重试次数，但耗尽后的状态转移不同。重试次数表示首次发送后的额外尝试，零表示不额外发送。
    支持用手动 .conf 配置值赋值，不按固件类型自动预设，也不把某台设备的状态提升成整条总线的状态。
12. **初始化状态。** 有初始化组的设备首先执行该组；成功后进入正常轮询。
    无回复时连续尝试当前请求，耗尽预算直接掉线，不再等待正常期的最长异常时间。
    有效 Modbus 异常应答停止本次初始化、记录错误，保持初始化未完成，间隔后重新尝试，
    不跳过失败包继续，也不因确实有回复而判通信掉线。重新尝试按此前确认的初始化流程从首包推进。
13. **正常轮询状态。** 各点按配置周期采集；请求超时重试耗尽进入答复异常。
    有效 Modbus 异常应答表示仍有通信，只记录操作错误并保留对应数据错误，不能仅因异常码进入无回复异常或掉线。
14. **答复异常状态。** 继续按原周期调度正常轮询组。进入该状态后，在设备允许的最长时间内仍无有效通信才掉线；
    重复失败不能不断重新开始等待时间。尚未正式掉线时恢复有效响应直接回正常轮询，不重新执行初始化。
15. **掉线状态。** 降低该设备轮询频率，每个探测间隔只发送规定首包。
    恢复有效响应后，有初始化组的设备进入初始化，首包成功则继续后续包；首包为有效异常应答则按初始化失败处理。
    无初始化组则回正常轮询。一个设备的等待和重试不得无限阻塞其他设备、本地采样或北向处理；
    同线物理收发仍串行，不能据此宣称链路可同时发送。
16. **结果归属与计数。** 仅正确归属于目标设备的有效应答证明通信存在，合法异常应答也属于有效应答。
    超时未得到有效应答才进入无回复处理；本地忙、队列满、校验拒绝或请求未实际发出不作为设备无回复。
    同一实际请求只更新一次最终结果，不能在头部检查后先记成功、载荷失败时再重复记失败。
    设备通信恢复与采样数据有效分开处理。
17. **显式下发最终不重试。** 包括非持久命令在内，显式下发失败只返回实际错误/超时，不自动重复发送，
    不触发答复异常状态。设备掉线本身不禁止显式尝试；能否执行仍遵循有效配置、物理接入及事务校验。
    这里不重试并不等于持久设置只发一帧；既有原值读取、意图日志、写入、读回及未决恢复契约保留。
    非持久命令不读回、不存 NVS、不在上线、初始化或重启恢复中自动重放。
18. **质量与缓存。** 设备掉线时统一使其 CO 采集点通信失效，保留最后值；北向读取失效点返回协议异常。
    重新上线不批量恢复质量，各点成功采样后分别恢复。已保存参数目标保持独立，不被采集反馈、初始化或掉线状态覆盖。
    本地和其他设备的有效测点继续按原映射读写，北向普通读继续缓存读取，不额外触发南向请求。
19. **错误诊断。** 模块按设备提供可查询的 RAM 错误记录和统计，至少能查看最近错误与错误次数；
    后续成功不能抹去历史错误。应用主动读取和清理，读取应得到一致结果；清理仅清记录和统计，
    不改变状态、点质量或触发初始化/命令重放，也不能重置用于状态推进的控制计时与重试预算。
20. **状态职责。** CO 维护南向设备状态与调度，模块报告自身错误和进度，应用协议层显式接入应用状态管理。
    显示、整机健康、看门狗和试运行确认策略仍归应用；远端掉线本身不作为整机停喂狗的理由。
    北向离线检测暂不实现，不将主站静默直接判为系统故障。
21. **存储降级。** 参数存储不可用时报告存储故障，继续本地采样、南向采集与北向读取。
    需要持久保存的写入必须失败，不先假报保存成功；IAP 保留保存失败时阻止升级提交/重启的既有约束。
    不因本次重构改变现有 NVS 键、记录格式、批量提交和未决恢复语义，或主动清空已保存值；
    原有记录格式不兼容时的重置及诊断策略保持不变。
22. **现有配置与传输边界。** 保留独立数据设备与虚拟转发入口、按入口选择读写映射和 IAP 段、静态 const 点表、
    Iterable Sections 登记及自动计数。协议解析留在可复用模块，vport 只处理协议无关的完整报文端口。
    应用保持物理映射、完整南向事务互斥及应答归属检查，保留 RAW/RTU、CRC、DE、发送错误和完成通知的现有职责。
23. **资源与迁移。** 显式迁移模块内全部相关 DP/CO/TR 执行上下文，而非只给隐藏创建行为换名字。
    线程容量和栈大小继续由模块 Kconfig 定义、由 .conf 手动配置，任务实际创建与绑定归应用；
    不增加未来资源预留或固件类型覆盖。现有业务 dp_/co_/tr_ 语义尽量保留，
    必须变化的生命周期、注册和配置接口同步迁移现用调用者及测试，不维护两套产品方案。

## Testing Decisions

1. **主要测试边界。** 优先使用一个协议装配集成场景：应用显式连接模块并提供执行上下文，
   经已有 CO/TR 完整报文入口注入请求和回复，用假南向端点产生正常、异常和无回复结果，
   通过北向完整响应、DP 公共读取、公开设备状态、错误读取/清理和实际发送记录断言行为。
   不为本功能公开私有状态机、队列数组、线程对象或链路内部路由器。
2. **复用先例。** 现有 `pipeline` 已覆盖样本交付、处理完成与转发链路，`collector` 已覆盖调度、
   有界队列和初始化失败，`shared_rs485` 已覆盖产品收发编排，`acquisition` 已覆盖启动与健康策略。
   `forwarding_devices` 已覆盖入口隔离与绑定迁移，`parameter_records` 和参数重启探针已覆盖独立进程存储验证。
   在这些公开入口和夹具上扩展，不以新建多套模块 mock 作为首选。
3. **好的测试。** 断言收到什么报文、发送多少次、何时具备服务能力、公开状态是什么、缓存质量是否有效、
   写入是否持久等外部契约。可以记录假端点的发送顺序及时间，不能以私有结构布局、函数调用次数或线程名称代替验收。
   使用短的显式测试周期和完成事件验证边界，避免等待产品级长周期或依赖无界 sleep。
4. **启动与连接。** 模块初始化后、应用放行任务前不应主动采集或开放未完成的服务。
   验证缺少必要注册或配置错误明确失败，后端在参数加载/恢复前绑定，远端无回复不阻塞本地成功启动。
   本地采样未推进时，北向服务和通信维护仍独立运行；通用模块不隐式连接 CO/DP。
5. **初始化与恢复矩阵。** 验证首次启动、全部初始化成功、首包成功后继续后续包、后续包失败停止、
   初始化超时耗尽直接掉线、有效异常应答报错但不判掉线、间隔重试，以及无初始化组直接正常轮询。
   验证正常期短暂异常恢复不重新初始化，正式掉线恢复才重做初始化。
6. **组包边界。** 通过发送记录验证顺序、连续合并和长度拆分；覆盖不同设备、功能码、阶段、周期、
   地址空洞、多字测点及 DP 批容量边界。确认掉线只探测约定首包，有/无初始化组分别选择正确首包，
   仅下发命令不意外进入采集组。验证毫秒周期值不截断，不为测试等待实际 60 秒。
7. **状态与重试矩阵。** 对多台同端口设备配置不同策略，验证额外重试次数、正常期耗尽后进入答复异常、
   异常期间仍正常轮询、最长异常时间到期进入掉线、掉线降频，以及有效响应恢复。
   一台设备失败时另一台及北向、本地采样继续推进。本地未发出请求不累计设备无回复，
   错误归属或无效回复不能假报通信恢复，同一次请求不重复计结果。
8. **下发与事务。** 显式写超时及有效异常应答均不自动重试，不因失败触发答复异常。
   离线时仍可尝试，完成返回真实结果；非持久命令只执行一次，不由上线或恢复重放。
   持久设置保留原事务、读回和丢失应答恢复，不能为了不重试而删除必要事务步骤。
9. **质量与诊断。** 掉线使该设备全部采集点失效并保留旧值，北向返回异常；上线后逐点成功采样才恢复有效。
   成功通信保留历史错误；应用读取与清理可并发安全使用，清理不使状态、计时或质量恢复，也不触发报文发送。
   其他设备、本地测点及已保存参数目标不受该设备失效或清理影响。
10. **存储与 IAP。** 在同一装配场景注入参数存储故障，证明采样、采集和读取继续，持久写明确失败，
    IAP 保存失败仍阻止提交/重启。沿用独立进程 Flash 夹具验证旧参数值可加载、没有因本次重构触发格式重置，
    丢失应答不造成非持久命令自动重放。
11. **回归与资源。** 运行相关 DP/CO/TR 独立模块与关闭适配器等现有可选构建，完整主机/native 回归，
    当前 IDU／MCUboot／IAPv3 固件构建、验签及导出检查。记录 Flash、RAM、实际任务资源变化，
    不把测试夹具容量或编译通过当作产品栈余量证明。实物 RS485 仲裁、DE 时序、性能和掉电行为单独记录。
12. **边界核对。** 本次生成规格时已向用户展示上述公开入口的主要测试边界并征询意见；
    该核对仅涉及测试入口，不重新访谈已确认的产品行为。未收到测试边界答复时，不将其记成用户已确认的选择。

## Out of Scope

- 本次规格发布直接实施运行代码、拆分全部实施任务、创建远端 Issue 或推送提交。
- 北向离线检测及新的主站静默判定；后续由应用协议层设计。
- CAN、以太网、新的 Modbus 传输格式、分帧或外部多主 RS485 仲裁保证。
- 运行期动态增删设备、热替换点表、动态切换站号来源或国家参数。
- 修改数据设备/信号身份、寄存器业务布局、参数 NVS 格式、Flash 分区、密钥或 IAPv3 线协议。
- 恢复 ARC 包装层、AIDC 产品分支、旧 MV-IO 特殊协议、全局转发表或本地设备充当转发入口。
- 错误日志持久化、错误清理触发设备恢复、显式命令自动重试或上线后自动重放命令。
- 接管 Zephyr 内核/子系统执行上下文，或扩展为硬件、IAP 等全部模块的任务所有权迁移。
- 为未来端口预留线程栈、按固件类型自动配置资源，以及承诺未经测量的内存或性能收益。
