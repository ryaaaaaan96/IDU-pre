# status 按职责分类

按用户要求拆分 LED、外部看门狗与任务监控接口：

- status.c：整机阶段、故障、降级诊断、镜像确认及单个后台工作。
- led.c：GPIO 初始化、运行起点、翻转及终止常亮。
- watchdog.c：外部 GPIO 喂狗适配、调试跳过、错误查询及检查。
- task_monitor.c：任务登记、心跳、永久休眠、期限排序及超时快照。
- internal.h：仅内部可见的运行阶段、共享状态锁及协作接口；对外仍使用 status.h。

status.c 从 380 行降为 181 行。LED 不再检查看门狗；后台工作依次维护两者。
任务链表和超时记录单独私有，仍与故障处理共用状态锁并在释放锁后报告。
合并两处最早期限选择、两处看门狗错误处理，四态下运行切换明确为 STARTING -> RUN。
初始化的重复调用检查移入状态锁。未新增线程、定时器或业务登记项。

验证：任务监控 12、系统编排 39、runtime 16 个独立进程场景全部通过，覆盖
LED 初始化/输出失败、故障后不访问未就绪引脚、并发故障常亮、初始化留驻持续喂狗、
调试跳过、重复故障、任务期限重排及超时停止/复位。共 67 场景。
