# 处理点表内聚默认值、范围与恢复策略

Status: accepted

## 现状

`app/protocol/tables/process.c` 已同时保存处理表与 `parameters[]`，
但二者仍分别定义信号；私有 `point_parameter` 重复维护设备/信号键。
默认值和恢复策略经应用回调交给 DP，通用配置读取逻辑仍留在应用中。

## 已确认方案

1. 扩展处理点表行，将 `DM_SIG_DATA_S` 默认值、上下限和恢复策略直接
   内嵌到每个信号定义中。不为保持参考结构而增加平行配置数组。
   配置仍为 `static const`，通过原有 Iterable Sections 登记。
2. 删除独立 `parameters[]` 和私有 `point_parameter`，取消其 U16/U32/WORDS
   行宏，用显式初始化器维护配置。`dev_id` 由设备挂表提供，不在每行重复。
3. DP 直接解释默认值、范围和恢复策略；IDU 不再注册默认值/范围及恢复策略的
   查表桥接回调。通用模块仍不引用产品信号号、头文件或固定设备号。
4. 通用值内嵌在处理点表；国家差异保留可选的稀疏覆盖入口，避免在同一处理表中
   重复 `sig_id`。当前只使用 COMMON，不增加运行期国家切换或自动覆盖已保存值。
   未知国家和无效设备/信号仍明确报错。
5. 恢复策略表示“是否参与主动恢复默认”；不表示启动时覆盖 NVS，
   也不同于 `dp_params_recover()` 的未决事务恢复。策略须有省略时的默认态，
   持久参数默认允许恢复，以 `FLAG_NO_RESTORE` 禁止，不增加独立 bool 字段。
6. 省略默认值时采用零值；范围统一由 `FLAG_RANGE_CHECK` 控制，未开启时使用类型范围，
   开启且双零时只允许零。旧回调保留双零不限制的适配规则。
   大数组的空默认指针由 DP 解释为全零，不再要求应用维护零填充数组。
   显式数组初值保持静态 const 存储期和现有字节顺序。
7. 原设置/读取回调、FLAG_COLLECT、Flash 保存策略和 RAM 动态默认/范围覆盖保持独立。
   旧接口的适配如仍有模块使用，应由 DP 内部承接，不让产品维护两份配置。

## 验收条件

- 单个点的身份、类型、标志、业务回调、默认值、范围及恢复策略在同一处维护。
- 现有五个持久参数的键、类型、宽度、顺序及派生存储标志不变；已有 NVS 优先于默认。
- 覆盖零默认、数组、有符号范围、恢复开关、缺省策略和未知国家查询。
- 状态/命令回调、南向下发、动态范围覆盖及掉电恢复继续通过相关回归。
- 构建验证配置仍在 Flash，记录 Flash/RAM 的实测变化。
