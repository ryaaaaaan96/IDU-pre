# Transmit 重新设计讨论

状态：讨论中，尚未授权实现；以下为已确认方向，不代表当前运行能力。

## 已确认

- 采用 transmit、modbus、vport 三个模块的职责划分，历史实现仅作参考。
- transmit 只承接对外从机协议，当前支持范围计划为 Modbus，以后其他对外协议也接入 transmit。
- transmit 主动调用 modbus；增加协议时允许修改 transmit，暂不设计协议注册框架。
- 每个转发入口有自己的对外地址，转发通过表配置。
- 入口配置表引用测点转发表；同一逻辑端口允许多个从机地址，端口与从机地址组合唯一。
- 测点映射使用 device_id + signal_index，应用通过枚举标识设备及 process 行索引。
- 一行映射一个完整测点，以起始寄存器及占用长度描述 Modbus 地址范围。
- 转发表显式配置协议表示类型、字序及只读/只写/读写权限；业务换算由 transmit 维护。
- 多寄存器默认高字在前；寄存器内部线路编码遵循 Modbus 大端规则。
- 每行可选读写转换回调；未配置时按声明类型直接转换，转换不承担业务动作。
- 允许读取完整测点中的部分寄存器；写入必须覆盖完整测点，禁止隐式读改写。
- 请求涉及地址空洞则整笔拒绝，不补零；执行前检查整个请求的地址覆盖、权限及完整写入要求。
- 多点写按地址顺序执行，首个错误停止，不承诺跨点事务或回滚；执行前检查类型、长度及转换。
