# Transmit 重新设计讨论

状态：讨论中，尚未授权实现；以下为已确认方向，不代表当前运行能力。

## 已确认

- 采用 transmit、modbus、vport 三个模块的职责划分，历史实现仅作参考。
- transmit 只承接对外从机协议，当前支持范围计划为 Modbus，以后其他对外协议也接入 transmit。
- transmit 主动调用 modbus；增加协议时允许修改 transmit，暂不设计协议注册框架。
- 每个转发入口有自己的对外地址，转发通过表配置。
- 入口配置表引用测点转发表；多个从机由多个实例配置，不在一个虚拟端口下登记多个 Modbus 从机。
- 测点映射使用 device_id + signal_index，应用通过枚举标识设备及 process 行索引。
- 一行映射一个完整测点，以起始寄存器及占用长度描述 Modbus 地址范围。
- 转发表显式配置协议表示类型、字序及只读/只写/读写权限；业务换算由 transmit 维护。
- 多寄存器默认高字在前；寄存器内部线路编码遵循 Modbus 大端规则。
- 每行可选读写转换回调；未配置时按声明类型直接转换，转换不承担业务动作。
- 允许读取完整测点中的部分寄存器；写入必须覆盖完整测点，禁止隐式读改写。
- 请求涉及地址空洞则整笔拒绝，不补零；执行前检查整个请求的地址覆盖、权限及完整写入要求。
- 多点写按地址顺序执行，首个错误停止，不承诺跨点事务或回滚；执行前检查类型、长度及转换。

## 后续确认与修订

- APP 的 protocol 创建线程；transmit 仅提供接口。同一逻辑链路串行，不同链路可并行。
- CAN ID、回复目标及 CAN 分片重组由 APP 管理，vport 与 transmit 不感知 CAN ID。
- 配置启动时登记，运行期常驻只读；多点读取接受逐点快照。
- 修订此前完整报文假设：vport 统一不同端口的访问，不强制完整报文；允许逐字节输入 transmit。
- transmit 负责同一逻辑端口的多协议分派；登记时声明支持哪些协议，主动调用协议模块。
- 首版覆盖 Modbus 01/02/03/04/05/06/15/16，地址为报文零基地址。
- 支持 Modbus 广播写入且不响应；多入口广播的具体分派及去重规则尚待明确。
- 待确定字节流帧边界事件、协议识别冲突、接收上下文及缓冲区生命周期。

## 当前报文基础模型（2026-10-30 确认）

- 统一接收字节与事件，由具体协议决定帧边界。
- APP protocol/port.c 提供字节块及真实接收事件，负责物理口接入、虚拟端口分发及发送协调。
- vport 不判帧，输入块边界不等于报文边界。
- 内容判帧协议依据帧头、长度或结束符提取报文；Modbus RTU 依据实际接收时序及静默边界判帧。
- 此基础模型不限定流式协议必须独占实例；混合协议采用下文的锁定调度规则。
- 一个 transmit 实例内每类协议最多一个实例，Modbus 对应一个从机；多个 transmit 实例通过表登记。

## 锁定调度（2026-10-31 确认）

- transmit 持有未消费数据及接收边界信息；协议只检查，不自行删除缓存。
- 判帧与业务执行分离；确认完整有效后才执行 DP 操作及响应。
- 所有协议从共同缓存起点检查，不自行搜索并跳过前缀。
- 首次从第一个登记协议开始锁定；数据不足时等待，不并行探测其他协议。
- 当前协议完整有效时执行并消费对应帧，继续保持协议锁定。
- 当前协议明确解析不匹配时，按登记顺序环形切换，下一协议检查原始未消费数据及已有事件。
- 业务错误不触发协议切换；例如地址不存在或 DP 写入失败，仍由已选协议处理。
- 每个协议必须有有限的候选报文接收期限及最大报文长度，不能无限等待。
  接收期限从候选报文开始计算，不因新字节无限延长；到期或协议长度超限须结束本次判定。
- 本规则替代 Q37 的“未确定也继续探测下一协议”；Q44 的无锁定建议未采纳。
- 无候选数据时不启动接收期限，不因正常空闲轮转协议。
- 协议切换沿用数据原始接收时间与已有事件，不重启计时；先检查是否完整有效，再判断等待是否超期。
- 每轮每个协议最多检查一次；全部不匹配后由 transmit 丢弃一个前缀字节，从新共同起点重新检查。
  保留真实边界信息，不将丢弃前缀后产生的 RTU 残片视为合法新帧。
- 接收丢字节、硬件错误或缓存溢出时中止受影响的候选数据，清理解析状态，等待有效接收起点。
  普通协议 CRC 不匹配仍采用协议轮转，不与底层接收损坏混为一谈。
- APP protocol 线程以有期限的接收等待驱动 transmit 超时推进；transmit 不创建定时器或工作队列。
  半帧后没有新数据时仍须推进超时；实际接收时间和边界不能以线程处理时间替代。
- 每实例登记时按配置一次分配固定接收及发送缓存，由 transmit 管理，运行期不扩容或申请内存。
  登记失败清理资源，接收容量至少覆盖该实例全部协议中最大的合法报文。
- vport 调用 APP 的同步带超时发送回调；返回前完成或中止发送，不保留 transmit 发送缓存指针。
  CAN 分片、UART 方向控制和物理发送互斥由 APP 负责。
- 已执行业务的请求即使响应发送失败也须消费，返回发送错误，不自动重放业务或重发响应，不解除协议锁定。
  主站重试作为新请求，模块不承诺业务恰好执行一次；广播按规则静默消费。
