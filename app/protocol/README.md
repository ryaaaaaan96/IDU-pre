# 产品协议与 process 点表

protocol_init() 先初始化 DP，登记 21 行本地 process，再初始化 APP 转发端口。
转发属于产品必需功能，不设置单独产品开关；通用模块保留 CONFIG_TRANSMIT。
`tables/process.c` 描述内部类型、范围、初值及持久化；`tables/forward.c` 独立配置北向协议映射。
设备使用 protocol_device_id_t，点行使用 process_signal_index_t，协议地址与稳定 key、行顺序独立。
采样周期、标签和保存地址持久化；其他点启动使用初值。

## UART 接入

`port.c` 持有协议线程、ISR 接收队列及 RS485 发送控制。
`idu-forward` 指向 `idu,forward-port` 节点，默认使用父 UART，也可通过 uart 属性显式引用控制器。
本板为 USART2，115200 8N1、PA15 方向控制；USART0 Shell 保持独立。
标准功能码委托 Zephyr RAW 服务端；MODBUS_SERIAL 禁用，物理 UART 仍由 APP 独占。
当前 MODBUS_NUMOF_RAW_ADU=1；增加 Modbus 实例时需调整，上限为 4。
接收逐字节记录硬件周期扩展后的单调微秒，线程按顺序交付，再在队列为空时推进超时。
发送通过中断填充 FIFO，等最后字符完成后回到接收；超时中止，不保留发送指针。
终止故障后 APP 不再提交新业务。CAN ID、重组与共享链路映射以后由这里扩展，不进入模块。

站号从 PROCESS_SAVED_ADDRESS 启动时读取，默认 1，允许 1–246；写保存地址只影响下次启动。
PROCESS_ADDRESS 表示本次启动的生效地址，范围与保存地址一致。
实例及协议通过常驻表登记，目前一个实例、一个 Modbus RTU 从机，其他协议尚未装配。
没有南向采集或透传。启用 IDU_IAPV3 时装配完整 ADU 地址段回调，保留旧 IAPv3 线协议。

## 测试寄存器（零基地址）

forward.c 仅保留独立测试映射，不兼容历史协议地址；DP 点作为数据源，不复制旧转发表。
不同地址空间中的相同地址互不冲突。
转发行使用 tr_modbus_point_t；协议地址和字序在外层，DP 身份、对外类型与放缩在 mapping 中。
应用通过 transmit 登记实例，Modbus 和 DP 的调用由模块内部完成。

| 功能码 | 地址 | 内容 | 覆盖项 |
| --- | ---: | --- | --- |
| 03/06/16 | 0 | 采样周期 U16，100–1000 ms | 单寄存器读写、范围拒绝 |
| 03/16 | 2–3 | 同一采样周期 U32，低字在前 | 字序、类型转换、部分读与拒绝部分写 |
| 03/16 | 4–5 | 同一采样周期 ×100，U32，高字在前 | 双向放缩、先逆换算后写 DP |
| 03/16 | 8–15 | 标签 WORDS | 数组读写、拒绝不完整写入 |
| 04 | 0 | DI 位图 U16 | 只读寄存器 |
| 04 | 1 | 第一路电流按 S16 输出 | 有符号类型、低位转换 |
| 02 | 0–15 | DI 各位 | 位读取和截取 |
| 01/05/15 | 0 | 虚拟模式低一位 | 单线圈与多线圈读写 |

未配置地址用于异常 02 测试；站号默认 1，广播写站号 0，不返回响应。
采样周期三组地址共用一个 DP 点，可交叉读回验证；例如写 0 为 600，
读 2–3 得到 600、0，读 4–5 得到 0、60000。
线圈写入会将虚拟模式设为 0 或 1，仅用于接口测试，不启用南向采集。

参数写成功仅代表 RAM 更新，默认五秒延后保存；重启前调用方须停止修改并 dp_flush。
CRC、超时、错误长度、其他站号及发送失败等用例通过报文或接入层注入，不额外占用寄存器。

## IAPv3 地址段

forward.c 的 protocol_upgrade_routes 保留起始地址 20003、20049–20104、31996–31997。
APP 将匹配请求交给 iap_route(0, request, response)，不经过 DP 或标准功能码数量检查。
CRC、RTU 边界和站号由转发入口先校验；精确包长、功能码与会话由接收器检查。
广播不会发出响应。关闭 IDU_IAPV3 不装配这些地址段，普通测点配置不变。

升级配置使用 CONFIG_MODBUS_BUFFER_SIZE=1100 的接收缓存、500 ms 整帧期限，
发送缓存仍为 256 字节。APP 线程栈为 8192 字节；IAP 构建的转发堆预算为 16384 字节，
另有独立 IAP 解包堆预算。115200 下约 1 KiB 长帧需要约 90 ms，不能沿用短帧缓冲。
实板连续上传、RS485 方向及旧上位机互通仍待验证。
